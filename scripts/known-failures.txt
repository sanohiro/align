# Known-failing workspace tests, the baseline scripts/run-suite-binaries.sh
# judges the nightly run against.
#
#   <package-dir>::<kind>::<target><TAB><test name>[<TAB>env]
#
# A plain line is a STRICT expectation in both directions: that test must fail,
# and the moment it passes the nightly turns red so the line gets deleted in
# the same change that fixed it. That ratchet is the point — a manifest is not
# a place for a test to retire.
#
# A third field of "env" marks a test whose outcome depends on something the
# nightly runner does not provide (an environment variable, a network, a
# service). It still runs, and it may pass or fail without changing the
# verdict. Reserve it for genuine environment dependence, never for flakiness:
# a flaky test is a bug, and hiding it here removes the only thing that would
# have reported it.
#
# Two synthetic test names exist for binary-level outcomes:
#   <binary-exit-N>            exited N without libtest naming a failed test
#   <binary-did-not-report>    never reached libtest's summary (crash or cap)
#
# Comments and blank lines are ignored. Keep entries sorted by target, and give
# each one a preceding comment naming the issue whose fix deletes it.
#
# HISTORY. A 2026-08-29 four-core run at 9c0cf23f refreshed a baseline whose
# every entry has since been deleted by the change that fixed it: the
# projected-storage consumer closure removed eleven rows, the direct-owned JSON
# parity owner removed the stale bounded-schema row, the PGO owner restored the
# stable missing-profile diagnostic, and #1101 removed the last two — the
# #1097 `analysis_coverage` pair. None of the entries below descends from it.
#
# The detector then produced no verdict at all from 2026-08-31 to 2026-09-17:
# the suite outgrew one runner's 30-minute budget and every night was cancelled
# (#1098). The sharded nightly's first complete verdict is run 35283248096;
# every entry below was named by it, was confirmed to be pre-existing on main,
# and carries a triage issue whose fix deletes its line. A 2026-09-19 change
# deleted the #1105/#1107/#1108 lines and repaired two untracked first-night
# failures (vectorize_shapes's x86 owners and http_headers_view) that were
# test-harness defects, not product regressions.
#
# EVERY line here is strict. None is "env": each one is a defect or a stale
# expectation with a named owner, not a dependence on something the runner does
# not provide.
#
# align_driver::test::pkg_db_a1 and align_driver::test::pkg_db_q4b exceeded
# the 900s per-binary cap on 2026-09-18 (#1109) because every owner test drove
# an opt-level 0 compiler. `[profile.dev] opt-level = 1`
# (docs/impl/21-build-perf-plan.md item 8) cut both binaries roughly 4x. A
# binary that still exceeds the cap is never listed here, for the same reason
# as before: a synthetic line would excuse a target that never produced a
# trustworthy outcome at all, retiring all of its tests from the detector —
# the opposite of what every line here is for.
