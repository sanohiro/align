# Known-failing workspace tests, the baseline scripts/run-suite-binaries.sh
# judges the nightly run against.
#
#   <package-dir>::<kind>::<target><TAB><test name>[<TAB>env]
#
# A plain line is a STRICT expectation in both directions: that test must fail,
# and the moment it passes the nightly turns red so the line gets deleted in
# the same change that fixed it. That ratchet is the point — a manifest is not
# a place for a test to retire.
#
# A third field of "env" marks a test whose outcome depends on something the
# nightly runner does not provide (an environment variable, a network, a
# service). It still runs, and it may pass or fail without changing the
# verdict. Reserve it for genuine environment dependence, never for flakiness:
# a flaky test is a bug, and hiding it here removes the only thing that would
# have reported it.
#
# Two synthetic test names exist for binary-level outcomes:
#   <binary-exit-N>            exited N without libtest naming a failed test
#   <binary-did-not-report>    never reached libtest's summary (crash or cap)
#
# Comments and blank lines are ignored. Keep entries sorted by target.
#
# baseline refreshed by the 2026-08-29 four-core run at 9c0cf23f; each original
# entry reproduced in its owner binary after the detector completed all 216
# targets. The projected-storage consumer closure removed eleven rows, and the
# direct-owned JSON parity owner removed the stale bounded-schema row, and the
# PGO owner restored the stable missing-profile diagnostic.
#
# The detector then produced no verdict at all from 2026-08-31 to 2026-09-17:
# the suite outgrew one runner's 30-minute budget and every night was cancelled
# (#1098). The sharded nightly's first complete Linux x86_64 verdict is run
# 35283248096; every entry below was named by it, was confirmed to be
# pre-existing on main, and carries a triage issue whose fix deletes its line.
#
# EVERY line here is strict. None is "env": each one is a defect or a stale
# expectation with a named owner, not a dependence on something the runner does
# not provide. Nine of the twelve reproduce on aarch64 macOS as well; the three
# marked Linux-only were verified to pass locally and must be fixed and
# re-verified on Linux or in a container.
#
# #1102: #937 (384d7744) widened the function-value signature rule and added the
# align_rt_http_headers_* entry points; three owners still assert the removed
# restrictions. Reproduces on both platforms.
# #1103: #1048/#1051/#1054 (76dcb12b) shipped owned field replacement; two
# owners still assert it is unsupported. Reproduces on both platforms.
# #1104: Move-resource formation rejections stopped firing for a branch-join
# return and a slice view. Suspected soundness regression, suspect not yet
# isolated. Reproduces on both platforms.
# #1105: two codegen owners bind their IR text scanners to the first match in
# the whole module, which is the wrong line/byte range on Linux x86_64.
# Linux-only.
# #1106: the CLI per-unit build no longer byte-matches the whole-program
# reference (different e_entry and e_shoff). Linux-only.
# #1107: only two of three pkg.ws automatic-reply transport failures beat the
# ordinary protocol result. Linux-only.
# #1108: under the PollZero capture failpoint align_rt_command_run returns 4
# instead of 0. Linux-only.
#
# Deliberately NOT listed: align_driver::test::pkg_db_a1, which exceeds the
# 900s per-binary cap and reports <binary-did-not-report> (#1109). A synthetic
# line for it would retire all 22 of its tests from the detector, which is
# exactly what the ratchet above exists to prevent. That shard stays red until
# its cost is cut, and pkg_db_a1 remains covered in full by the required
# db-postgres job and scripts/db-verify-local.sh.
