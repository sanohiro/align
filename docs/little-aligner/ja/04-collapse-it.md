# 4. Collapse It

> 🌐 [English](../04-collapse-it.md) · **日本語**

**Q1.** `sum` と `count` にはもう出会いました。`[5, 3, 8, 1].min()` は何ですか？

**A1.** `1`。

---

**Q2.** そして `[5, 3, 8, 1].max()` は？

**A2.** `8`。ここまでの集計処理は `sum`、`count`、`min`、`max`。どれも複数の値を一つにまとめます。

---

**Q3.** `[1, 2, 3, 4].any(fn x { x > 3 })` は何ですか？

**A3.** `true`。3より大きい要素が一つ以上あります。`all(fn x { x > 0 })` も、すべての要素が正なので `true` です。`any` と `all` は、どちらも `bool` を返します。

---

**Q4.** `[2, 4, 6].all(fn x { x % 2 == 0 })` は何ですか？

**A4.** `true`。では `[2, 4, 7]` なら？ `7` が条件を満たさないので `false` です。ただし、Align の `any` と `all` は**短絡しません**。答えが決まっても最後まで走査します。この方式は、ベクトル化に適しています（13章）。

---

**Q5.** ぴったりの集計処理がないとしましょう。今度は *積* が欲しい。どうしますか？

**A5.** `reduce` で、各要素を掛け合わせます。

```align
[1, 2, 3, 4].reduce(1, fn acc, x { acc * x })
```

`24`。

---

**Q6.** なぜ先頭に `1` があるのですか？

**A6.** 累積値 `acc` の初期値です。`1` から始めて、各要素を掛けていきます。和なら初期値は `0` です。要素がなければ、この初期値がそのまま答えになります。

---

**Q7.** `fn acc, x { acc * x }` で、どちらがどちらですか？

**A7.** `acc` はこれまでの答え、`x` は次の要素。ラムダは、次の要素をどう答えに組み込むかを指定しています。

---

**Q8.** `reduce` を使って、`sum` を自分で書いてください。

**A8.** `xs.reduce(0, fn acc, x { acc + x })`。`reduce` なら、まとめ方を自分で指定できます。単に合計が欲しいときは、`sum` のほうが意図を短く伝えられます。

---

**Q9.** `[1, 2, 3, 4].scan(0, fn acc, x { acc + x })` は何ですか？

**A9.** 途中までの和を並べた配列 `[1, 3, 6, 10]` です。`reduce` が最後の値だけを返すのに対し、`scan` は各段階の値を配列に保存します。`scan` 自体が実体化する**終端処理**なので、`to_array()` は不要です。返された配列をさらに集計することもできます。

---

**Q10.** では `[1, 2, 3, 4].scan(0, fn acc, x { acc + x }).max()` は何ですか？

**A10.** `10`。途中までの和の最大値です。負の数を含む配列でも考えてみてください。

---

**Q11.** `[3, 1, 2].map(fn x { x }).sort()` は何を返しますか？

**A11.** `[1, 2, 3]` という配列です。`sort` も、結果を配列に実体化する終端処理です。

---

**Q12.** そして `[10, 21, 32, 3].sort_by_key(fn x { -x })` の結果は？

**A12.** `[32, 21, 10, 3]`。符号を反転した値で並べ替える: `reverse` を一切使わずに降順です。

---

**Q13.** `[1, 2, 3, 4, 5].partition(fn x { x % 2 == 0 })` は何ですか？

**A13.** 一度に2つの配列: `([2, 4], [1, 3, 5])` — 条件を満たしたものと、そうでないもの。まとめて受け取りましょう: `(evens, odds) := ...`。

---

**Q14.** 空のスライスに対して、`any` と `all` は何を返しますか？

**A14.** `any` は `false`、`all` は `true`。条件を満たす要素はなく、条件に反する要素もありません。

---

**Q15.** 何もないものの `all` が `true` なのは、なぜ？

**A15.** 「条件に反する要素があるか？」と考えてみてください。空なら一つもありません。`sum` が空の入力に `0` を返すように、`all` は `true` を返します。

---

**Q16.** `[1, 2, 3, 4]` の2乗和は？

**A16.**

```align
[1, 2, 3, 4].map(fn x { x * x }).sum()
```

`30`。各要素を `map` で2乗し、`sum` で合計します。

---

**Q17.** 各要素を2乗した結果のうち、偶数になるものを数えます。先に2乗する必要はありますか？

**A17.** ありません。整数とその2乗では、偶奇が変わらないからです。

```align
[1, 2, 3, 4].where(fn x { x % 2 == 0 }).count()
```

`2`。個数だけが必要なので、2乗の計算は省けます。

---

**Q18.** 合計と個数を、一度の `reduce` で求めてください。

**A18.**

```align
pair := [2, 4, 6].reduce((0, 0), fn acc, x {
    (acc.0 + x, acc.1 + 1)
})
```

`pair` は `(12, 3)`。累積値をタプルにすれば、合計と個数を一緒に保持できます。

---

**Q19.** では整数の平均は？

**A19.** `pair.0 / pair.1`、つまり `4`。集計した合計を個数で割ります。入力が空かもしれないなら、ゼロで割らないよう、空の場合の扱いを先に決めてください。

---

**Q20.** `[3, -5, 4, 2]` の途中の合計は？

**A20.** `[3, -2, 2, 4]`。

```align
totals := [3, -5, 4, 2].scan(0, fn acc, x { acc + x })
```

`scan` がすでに配列を作っているので、`to_array()` は不要です。さらに呼ぶと、もう一つ配列を確保します。

---

**Q21.** 途中の合計の最大値は？

**A21.**

```align
[3, -5, 4, 2].scan(0, fn acc, x { acc + x }).max()
```

`4`。`scan` が保存した途中の合計から、`max` が最大値を求めます。

---

> **第四の戒律**
>
> *`reduce` には初期値とまとめ方を渡せ。`sum` や `count` で目的を表せるなら、その名前を使え。*
