# 15. Read It Four Ways

> 🌐 [English](../15-read-it-four-ways.md) · **日本語**

**Q1.** ここまでに習ったことを、1つの小さなプログラムで確かめられますか？

**A1.** 次のプログラムで、読み方を練習しましょう。

```align
Record { score: i64, valid: bool }

fn total(data: str) -> Result<i64, Error> {
    arena {
        rows: soa<Record> := json.decode(data)?
        return Ok(rows.where(.valid).score.sum())
    }
}
```

まず一度、ゆっくり読んでください。

---

**Q2.** デコードした3件のレコードが `(10, true)`、`(20, false)`、`(30, true)` だとします。`total` の答えは？

**A2.** `Ok(40)`。有効な行だけを残し、そのスコアを取り出して足します。これが**答えを読む**ということです。仕組みを考える前に、プログラムが何を求めるのかを確かめます。

---

**Q3.** なぜ答えから始めるのですか？ 面白いのは仕組みのほうでは？

**A3.** 答えが `40` でなくなる最適化はバグだからです。寿命の扱いがうまくても、結果が間違っていては役に立ちません。ほかの読み方でも、まず答えが変わらないことを確かめます。

---

**Q4.** 2度目は、データがどのように変わるかを追ってください。

**A4.** テキストを受け取り、`json.decode` で列に変えます。`where(.valid)` で有効な行を選び、`.score` でスコアを取り出し、`sum()` で合計します。これが**流れを読む**ということです。左から右へ、各段が何をするかを確かめます。

---

**Q5.** `where(.valid).score.sum()` は、いくつのループになりますか？

**A5.** 融合した1つのループです。ただし、関数全体が1回の走査で済むわけではありません。テキストのデコードが別にあり、その後で列を走査します。実際に行う処理を分けて数えましょう。

---

**Q6.** `Record` に `name`、`email`、`notes` もあったとします。融合したループが読む列は？

**A6.** `valid` と `score` です。ほかの列もありますが、この集計では読みません。9章の列ごとの配置と、5章のパイプラインの融合を一緒に使っています。

---

**Q7.** 3度目は、各値を誰が所有し、いつまで使えるかを確かめてください。

**A7.**

- `data` は、呼び出し元から借りた `str` のビューです。
- `rows` とその列は arena 内で使え、閉じる `}` で領域が解放されます。
- 最後の `i64` は Copy なので、`Ok` に包んで arena の外へ返せます。

これが**寿命を読む**ということです。各値がどの領域に属し、いつまで使えるかを追います。

---

**Q8.** 数は arena の外へ出られるのに、なぜ `rows` は出られないのですか？

**A8.** 数値は値そのものを持ち、arena 内のメモリを参照しないからです。`rows` は arena の領域を参照しています。そのまま返すと、解放されたメモリへのビューが残るため、型検査で拒否されます。

---

**Q9.** JSON が不正だったら？

**A9.** `?` で `total` から `Err` を返します。途中で関数を抜ける場合も arena の領域は解放されるので、メモリリークにはなりません。

---

**Q10.** 4度目は、機械がどんな処理を行うかを確かめてください。

**A10.** 入力をパースし、arena に列の領域を確保してから、必要な2列を1つのループで走査します。絞り込み後の配列は作らず、文字列の複製もしません。これが**仕事量を読む**ということです。走査の回数、読む列、確保とコピー、処理を抜ける箇所を確かめます。

---

**Q11.** 絞り込み後の配列を作っていないと、どうしてわかるのですか？

**A11.** `where` と `sum` の間に、配列を作る終端がないからです。配列が必要なら `.to_array()`、深いコピーが必要なら `.clone()` と書きます。コストが変わる操作は、ソースから読み取れます。

---

**Q12.** 代わりに、こう書くと？

```align
rows.where(.valid).score.to_array().sum()
```

**A12.** 答えは同じですが、仕事量が変わります。`to_array()` でスコアの配列を作り、`sum()` でその配列をもう一度走査します。配列が必要な場合もありますが、ここでは不要です。答えだけでは見えない違いを、仕事量から見つけられます。

---

**Q13.** `?` を `else` に置き換えられますか？

**A13.** はい。`else` 側でペイロードと同じ型の代替値を出すか、`else { return Err(Error.Invalid) }` のように関数を抜けられます。ただし `Result` の `else` は元のエラーを捨てます。そのエラーをそのまま渡すなら `?`、中身を調べて判断するなら `match` を使います。呼び出し元にどのエラーや代替値を返すかで選びましょう。

---

**Q14.** このプログラムのどこに `loop` が入りますか？

**A14.** 列の走査には使いません。すでにある各行に同じ操作をするので、パイプラインで書けます。`loop` を使うのは、EOF までブロックを読む、準備ができるまで再試行する、計算が収束するまで繰り返す、といった処理です。

---

**Q15.** では `match` が入るのは？

**A15.** デコードエラーの詳細を調べたり、直和型のフィールドをバリアントごとに処理したりする箇所です。`match` は値の種類による分岐、`loop` は繰り返しの制御、パイプラインは多数の要素の処理を受け持ちます。

---

**Q16.** 4つの読み方を、前を見ずに挙げてください。

**A16.**

1. **答え** — どんな値を求め、どんな失敗を返すか？
2. **流れ** — データはどう変わり、制御はどこへ進むか？
3. **寿命** — 各値を誰が所有し、いつまで使えるか？
4. **仕事量** — どのデータを読み、何回走査し、どこで確保・コピー・終了するか？

答えられないものがあれば、そこがまだ理解できていない部分です。

---

**Q17.** Align のソースから、なぜこの4つを読み取れるのですか？

**A17.** 各機能が、処理とそのコストを一緒に表すからです。パイプラインはデータの変換と融合できる範囲を、`soa` は使う列を、Move と arena は所有権と寿命を示します。`?`、`.clone()`、`.to_array()` を見れば、失敗時の終了、コピー、配列の確保がわかります。人が読むコードが、コンパイラによる解析や実行時の処理にもつながっています。

---

**Q18.** 本を閉じて答えてください。要件が「有効なスコアのうち、100より大きいものの件数を返す」に変わりました。最後の式をどう変えますか？

**A18.**

```align
return Ok(rows
    .where(.valid)
    .score
    .where(fn s { s > 100 })
    .count())
```

前の例を写さず、要件の文から書けたなら、パイプラインを使いこなせています。

---

**Q19.** 今度は「有効なスコアのうち、100より大きいものをすべて返す」です。何が変わりますか？

**A19.** 返り値の型は `Result<array<i64>, Error>` です。元の arena 内で `.to_array()` とするだけでは、その配列も arena に属してしまいます。同じ `Record` 宣言と `import core.json` を使い、ローカルな arena を持たない補助関数で結果を作ります。

```align
fn collect_scores(rows: soa<Record>) -> array<i64> =
    rows.where(.valid).score.where(fn score { score > 100 }).to_array()

fn scores(data: str) -> Result<array<i64>, Error> {
    arena {
        rows: soa<Record> := json.decode(data)?
        return Ok(collect_scores(rows))
    }
}
```

`rows` は、補助関数の呼び出し中に借りる SoA のビューです。補助関数の `to_array()` は、独立した結果の領域を確保します。呼び出し元の arena を暗黙に引き継ぐことはありません。要素は `i64` の値なので、入力の列を借りていません。一時的な列を解放した後も、呼び出し元は結果の配列を使えます。一方、要素が `str` のビューなら、その文字列への依存は残ります。配列を所有することと、各要素が独立していることは別です。

---

**Q20.** 「デコードに失敗したら、そのエラーを変更せず返す。成功したら件数を返す」という要件です。どの書き方を残しますか？

**A20.** `Result` と `?` です。`else` で代替値に置き換えると、求められたエラーを捨ててしまいます。このデコーダが返すのは `Error` であり、伝播するだけで行番号や詳しいパースエラーの説明が付くわけではありません。

---

**Q21.** 「EOF までブロックを読み、各ブロックの有効なスコアを合計する」なら、何を組み合わせますか？

**A21.** ブロックを読む外側に `loop`、各ブロックを処理する内側にパイプラインを使います。1つの問題でも、処理ごとに適した構文を組み合わせます。

---

**Q22.** 「入力は巨大で、必要なのは件数1つだけ」なら、`soa` とスキャナのどちらですか？

**A22.** スキャナです。後で再利用しない列を保存する必要はありません。結果が件数1つなら、途中で保持するデータも少なくできます。

---

**Q23.** 「20個の分析で、同じ5列を使い回す」なら？

**A23.** arena 内の `soa` です。一度デコードし、一連の分析が終わるまで列を保持します。処理の内容が変われば、適した方法も変わります。

---

**Q24.** Align の機能が身についたと言えるのは、どんなときですか？

**A24.** 定義を説明できるだけでなく、新しい問題で使うかどうかを選び、ほかの機能と組み合わせられるときです。実行する前に、答え・寿命・コストも説明できれば、理解を確かめられます。

---

>
