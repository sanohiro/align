# 8. Whose Is It?

> 🌐 [English](../08-whose-is-it.md) · **日本語**

**Q1.**

```align
a := 42
b := a
```

いま 42 はいくつ存在しますか?

**A1.** 2つ。数は **Copy** です。代入によって複製されます。それぞれ独立した値になります。

---

**Q2.**

```align
a := "hello".clone()    // an owned string
b := a
```

いま、所有する文字列はいくつありますか？

**A2.** 1つ。`string` はヒープ上のバッファを所有し、所有型の代入は **Move** になります。バッファが持ち主を替えたのです。今は `b` がそれを持っています。

---

**Q3.** では、その直後の `print(a.len())` は何をしますか？

**A3.** コンパイルエラーです。`a` はすでにムーブされているので使えません。いまバッファを所有しているのは `b` です。

---

**Q4.** なぜそんなに厳しいのですか？

**A4.** 所有者が一つなら、コンパイラが解放の責任を追えるからです。ガベージコレクタに回収を任せたり、ソースにライフタイム注釈を書いたりせずに管理できます。

---

**Q5.** でも、本当に文字列が2つ欲しいのです。

**A5.** `b := a.clone()` と書きます。文字列の内容を別のバッファにコピーするので、`a` と `b` がそれぞれ自分のバッファを所有します。確保とコピーを行う箇所が、コードに現れます。

---

**Q6.** どの型が Move ですか？

**A6.** `string`、`array<T>`、`buffer`、ファイルハンドルなど、リソースを所有する型です。数、`bool`、ビュー、Copy のフィールドだけを持つ構造体は Copy です。`string` を含む構造体は、その文字列も所有するため Move になります。

---

**Q7.** `.clone()` する前の `"hello"` は、どんな値ですか？

**A7.** リテラルのバイト列は、プログラムの実行中ずっと存在します。型は `str`。ポインタと長さを持つ**ビュー**です。ビューは Copy ですが、コピーするのはポインタと長さだけで、文字列の内容は複製しません。

---

**Q8.** さて `arena` です。これは何を表示しますか？

```align
fn shout(name: str) -> string {
    arena {
        s := template "hey, {name}!"
        return s.clone()
    }
}

print(shout("align"))
```

**A8.** `hey, align!`。`arena {}` の中で作る文字列テンプレートは、`arena` にメモリを確保します。ブロックを抜けるとその領域は解放されますが、この例では `.clone()` で結果を外へコピーしています。文字列の `+` は使えません。連結には文字列ビルダーを使います。

---

**Q9.** 複製なしで `return s` としたら？

**A9.** コンパイルエラーです。`s` は arena に確保された領域を参照しており、その領域は `}` で解放されます。外で使うには、`.clone()` で内容をコピーします。

---

**Q10.** `arena` はどんなときに使いますか？

**A10.** 同じタイミングで解放する値を、まとめて作るときです。ファイルの解析、リクエストの処理、バッチのデコードなどが当てはまります。その処理を `arena {}` で囲めば、一時領域をブロックの終わりでまとめて解放できます。

---

**Q11.** ガベージコレクタに回収を任せる方法とは、何が違いますか？

**A11.** `arena` は、複数の値をいつまで使うか、あらかじめわかっている場合に使います。それらを一つの領域に確保し、処理が終わったらまとめて解放します。個々の値がまだ必要かをガベージコレクタに調べさせる代わりに、寿命の区切りをプログラムで指定します。

---

**Q12.** もしループの中で10,000個の一時的な文字列を作り、それを1つずつ解放したとしたら、コストはどうなりますか？

**A12.** 個別の確保と解放には、そのたびにアロケータの管理処理が必要です。`arena` では通常、確保済みのブロック内でポインタを進め、足りなくなったら次のブロックを確保します。文字列自体を作る処理は必要ですが、確保と解放に伴う管理処理を減らせます。

---

**Q13.** 新しいデータを作るとき、何を基準に選べばよいでしょう？

**A13.** まず、*いつまで使うのか*を考えます。

- 今のスコープだけ → 通常の値として持つ
- 一まとまりの処理の間 → arena に確保し、外で必要な結果だけ `.clone()`
- それより長く使う → 所有する型にして、必要な先へムーブする
- データを読むだけ → ビュー。参照先のデータはコピーしない

---

**Q14.** このバッファを、いま誰が所有していますか？

**A14.** 最後にムーブした先の変数です。ソースをたどれば確認でき、ムーブ済みの変数を使おうとするとコンパイラが拒否します。

---

**Q15.** 一つの配列、二つのスライスです。

```align
xs := [10, 20, 30]
a := xs[0..2]
b := a
```

配列はいくつありますか？

**A15.** 一つです。`a` と `b` は同じ2要素を参照するビューです。ビューをコピーしても、要素のコピーは作りません。

---

**Q16.** どちらのビューも `xs` より長生きできますか？

**A16.** できません。コンパイラが借用元の寿命を追い、ビューがその範囲を越えて使われないことを確認します。

---

**Q17.** 所有者を追ってください。

```align
a := "red".clone()
b := a
c := b.clone()
```

まだ使える名前は？

**A17.** `b` と `c`。`a` の所有権は `b` に移ったので、`a` は使えません。`clone` は `b` のバッファを残したまま、`c` のために別のバッファを作ります。

---

**Q18.** ここで `d := b`。文字列を所有する名前は？

**A18.** `c` と `d`。元のバッファは `b` から `d` へ移り、複製されたバッファは `c` が所有したままです。

---

**Q19.** 関数が `string` を値で受け取ります。`d` を渡すと？

**A19.** 所有権が関数へ移り、呼び出し元の `d` は使えなくなります。関数は、戻り値などとして所有権をさらに移さない限り、その文字列を解放します。戻ってきた文字列は新しい変数で受け取ります。元の `d` が再び使えるようになるわけではありません。

---

**Q20.** 関数はテキストを読むだけです。よりよい引数は？

**A20.** `str` です。

```align
fn count_bytes(s: str) -> i64 = s.len()
```

文字列の所有権を保ったまま、ビューを渡せます。`string` を値で渡すと所有権が移り、`str` を渡すと内容を借用して読めます。

---

**Q21.** 一時的な文字列を10個作り、一つを返します。コピーはどこに現れるべき？

**A21.**

```align
arena {
    chosen := build_choice(...)
    return chosen.clone()
}
```

一時的な文字列は同じ `arena` にまとめ、外で使う一つだけをコピーします。

---

**Q22.** 最初に役立つ問いは「スタックかヒープか」、それとも「どれだけ生きるか」？

**A22.** 「いつまで使うか」です。読むだけなら借用したビュー、処理の終わりでまとめて解放するなら `arena`、その後も必要なら所有する値、というように考えます。

---

**Q23.** 名前の文字列を所有するレコードがあります。所有権を渡さずに、関数で中身を調べられますか？

**A23.** はい。共有の `borrow` パラメータを使います。

```align
Profile { name: string, visits: i64 }

fn name_size(borrow p: Profile) -> i64 = p.name.len()

fn main() -> i32 {
    p := Profile { name: "Ada".clone(), visits: 0 }
    print(name_size(p))    // 3
    print(p.name.len())    // 3 — the caller still owns p
    return 0
}
```

`borrow` がなければ、この Move 型のレコードの所有権は関数へ移ります。呼び出しは `name_size(p)` のままで、渡し方はパラメータの宣言に書きます。

---

**Q24.** `name_size` の中で `p.visits` を更新してもよいですか？

**A24.** いいえ。共有借用は読み取り専用です。呼び出し元のレコードを更新するなら、パラメータを次のように宣言します。

```align
fn visit(borrow mut p: Profile) {
    p.visits = p.visits + 1
}
```

呼び出し元では `mut p` と宣言して、`visit(p)` を呼びます。レコードの所有権は呼び出し元に残り、`visits` が `1` に変わります。関数は呼び出し中、その値を排他的に使います。必要なのが名前の文字列だけなら `str` で十分です。レコード全体を扱いたいときに借用を使います。

---

> **第八の戒律**
>
> *所有者は一度に一つ。同時に使い終わる値は `arena` にまとめよ。文字列の複製が必要なら、`.clone()` と書け。*
