# 10. Count Me by Name

> 🌐 [English](../10-count-me-by-name.md) · **日本語**

**Q1.** 1行に1件ずつ、売上を並べました。

```text
east 3
west 4
east 5
```

*地域ごと*の合計は？

**A1.** east は `8`、west は `4`。グループに分けてから足しました。この処理を、ハッシュマップを自分で組み立てずに書いてみましょう。

---

**Q2.** 地域 ID の `k` と売上額の `v` を持つ `soa` で、どう書きますか？

**A2.**

```align
g := s.group_by(.k).sum(.v)
```

一方のフィールドでグループに分け、もう一方を集計します。データ分析でよく使う形です。

---

**Q3.** 返ってくるのは何ですか？

**A3.** 2つの列がペアで返ります。`g.0` は重複のないキー、`g.1` は各キーの合計です。同じインデックスの要素同士が対応します。入力も出力も列なので、9章の操作をそのまま使えます。

---

**Q4.** 上の売上で、`g.0.count()` と `g.1.sum()` は何ですか？

**A4.** `2`（east と west）と `12`（全売上）です。グループに分けても、合計する値は変わりません。

---

**Q5.** `sum` のほかに、`group_by` の後には何が続けられますか？

**A5.** `min(.f)`、`max(.f)`、`count()` です。地域ごとの最小・最大の売上額や件数を求められます。`count` はフィールドを取りません。件数を数えるだけなら、値を見る必要がないからです。

---

**Q6.** `group_by` だけ先に書いて、集計は後に回せますか？

**A6.** いいえ。5章と同じく、`group_by` だけでは式が完成しません。何を集計するかまで、続けて書きます。

---

**Q7.** 名前をキーにして、合計・最大値・件数を求めます。3回走査するのですか？

**A7.** 1回にまとめられます。

```align
g := xs.group_by(.name).agg(sum(.a), max(.b), count())
```

`agg` は1回の走査で、キーごとに3つの集計値を更新します。`g.0` は名前、`g.1` は合計、続いて最大値、件数の列が返ります。

入力の型には注意が必要です。`agg` が受け取るのは、文字列をキーにした**構造体の配列**です。ここでの `xs` は、Q12 の `json.decode` で得るような、所有権を持つ `array<Row>` です。現在の `agg` は `soa` や整数キーには対応していません。`soa` にも使えるのは、Q2 の `group_by(.k).sum(.v)` のような単一の集計です。

---

**Q8.** なぜ1回にまとめたいのですか？

**A8.** 大きな表を何度も読むにはコストがかかるからです。1回にまとめれば、各行を一度読んで、そのキーの集計値をすべて更新できます。ハッシュ計算や各集計の計算は、引き続き必要です。

---

**Q9.** 文字列の `name` で、別々に5回グループ分けします。どんなコストが繰り返しかかりますか？

**A9.** 同じ文字列のハッシュ計算と比較を、5回繰り返すことになります。

---

**Q10.** それを減らすには？

**A10.** 先に名前を ID に置き換えます。

```align
e := xs.dict_encode(.name)          // intern the names → small ids
s := e.group_by(.name).sum(.a)      // these ride the ids —
c := e.group_by(.name).count()      //   no re-hashing
```

同じ名前を再利用できる ID に置き換える、辞書エンコーディングです。入力の型は `agg` と同じで、`xs` は所有権を持つ `array<Row>`、`.name` は文字列のキーです。

---

**Q11.** 列指向データベースでも使う手法が、何度も出てきますね。偶然ですか？

**A11.** いいえ。列ごとの配置、グループ集計、辞書エンコーディングは、データベースでも Align のプログラムでも、同じような処理に役立ちます。Align では、それらの操作をソースに直接書けます。

---

**Q12.** 練習です。`{"name":..., "a":..., "b":...}` というレコードを含む JSON から、重複のない名前と、名前ごとの `b` の最大値を、1回の集計で求めてください。

**A12.**

```align
xs: array<Row> := json.decode(data)?
g := xs.group_by(.name).agg(max(.b), count())
print(g.0.count())      // how many names
print(g.1.max())        // the largest of the per-name maxima
```

この集計では、名前ごとの最大値と件数を一緒に求めています。2つの `print` は、名前の種類数と、名前ごとの最大値のうち最も大きい値を表示します。

---

**Q13.** 「1回の走査」は「追加のメモリが不要」という意味ですか？

**A13.** いいえ。グループごとの途中の集計値を保持する表と、結果の列が必要です。おおよそキーの種類数に比例する領域を使います。`agg` は複数の集計で同じ表と走査を共有しますが、その領域が不要になるわけではありません。

---

**Q14.** すべての行のキーが異なる場合は？

**A14.** 集計結果は入力とほぼ同じ大きさになります。入力の行数だけでなく、グループ数も確認しましょう。

---

**Q15.** 文字列でグループ分けする前には、毎回 `dict_encode` を使うべきですか？

**A15.** いいえ。文字列の `group_by` は、その集計に必要な文字列の共有化を内部で行います。`dict_encode` が役立つのは、変換後の列を複数のグループ集計や比較で使い回す場合です。

---

**Q16.** 顧客ごとの注文額です。

```text
ada  10
bo    4
ada   3
bo    8
ada   2
```

顧客ごとの合計は？

**A16.** ada は `15`、bo は `12`。コードを書く前に、頭の中でグループに分けてみましょう。

---

**Q17.** フィールド `.customer` と `.amount` を使って書いてください。

**A17.** 入力は A7 と同じ形です。文字列をキーにした、所有権を持つ `array<Order>` を使います。

```align
orders: array<Order> := json.decode(data)?
g := orders.group_by(.customer).sum(.amount)
```

`g.0` が顧客、`g.1` が対応する合計額です。

---

**Q18.** 顧客ごとの最大の注文額と件数も必要です。グループ分けは3回ですか？

**A18.** 一度です。

```align
g := orders.group_by(.customer).agg(
    sum(.amount),
    max(.amount),
    count(),
)
```

キーの表を1つ持ち、グループごとに3つの集計値を更新します。Q16 で顧客名を使ったのは、`agg` が構造体の配列と文字列のキーを受け取るためです。数値のキーを使う場合は、単一の集計を別々に行います。

---

**Q19.** 顧客ごとの合計額 `g.1` を、さらに合計すると？

**A19.** `27`。入力の注文額をすべて足した値と同じです。グループに分けても、合計に含める値は変わりません。

---

**Q20.** 顧客ごとの最大値から、さらに最大値を求めると？

**A20.** `10`。全注文の中で最も大きい金額です。グループ集計の結果を、さらに集計できます。どの列を処理しているかを確かめながら読みましょう。

---

**Q21.** 5つのレポートで同じ顧客名を使い、それぞれ別の値を集計します。どんな最適化ができますか？

**A21.**

```align
encoded := orders.dict_encode(.customer)
sales := encoded.group_by(.customer).sum(.amount)
counts := encoded.group_by(.customer).count()
```

キーの列を一度エンコードし、複数の集計で使い回します。再利用するのは途中の `group_by` ではなく、`dict_encode` で変換したデータです。

---

> **第十の戒律**
>
> *グループ分けから集計まで続けて書け。複数の集計は一度にまとめ、繰り返し使う文字列のキーは一度だけ変換せよ。*
