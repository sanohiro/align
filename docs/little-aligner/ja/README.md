# The Little Aligner

> 🌐 [English](../README.md) · **日本語**

*『The Little Schemer』（邦題『Scheme手習い』）の伝統にならって。*

短い問答を通して Align を学ぶ**ドリル**です。パイプライン、`match`、Move、`arena`、列指向のデータ配置を、小さな例から順に練習します。構文やライブラリを調べたいときは、[ガイド](../../guide/ja/README.md)を参照してください。

目指すのは、初めての問題にも学んだ道具を使えるようになることです。データはどんな形か。各要素への処理なのか、場合分けなのか、条件を満たすまでの繰り返しなのか。誰がデータを所有し、いつまで使うのか。どの列を読み、どこでメモリを確保するのか。問いに答えながら、こうした判断を練習します。

## 使い方

本の横で **`align-repl` を開き、例を試しながら読み進めてください。** 問いを読んだら、まず自分で答えを予想します。それからコードを入力し、実行結果と本の答えを見比べてください。予想と違ったら、数問戻って、どこで考え違いをしたのか確かめてみましょう。大半の問いは、それまでに学んだことで答えられます。

次の問いでも使う定義は、そのまま残しておけます。値を変えたり、要素を増やしたり、空の入力を試したりするたびに、新しいファイルを作る必要はありません。少し変えて試すときも、実行する前に結果を予想してみてください。

答えが一言のことも、前の問いとよく似た問いもあります。何が変わったのかに注目してください。各章の最後には、覚えておきたいことを**戒律（Commandment）**としてまとめています。

読み終えたら、気に入ったプログラムを一つ選び、実行せずに読み直してください。答えを予想し、データの流れと寿命を追い、走査やメモリ確保、コピーの回数を数えます。[最後の章](15-read-it-four-ways.md)で、この読み方を練習します。

## 例を動かすには

インストールは、ガイドの[「はじめる」](../../guide/ja/01-getting-started.md)を参照してください。ターミナルから次のように起動します。

```text
$ align-repl
align> 1 + 2
3
```

多くの問いは、式や短いコードの断片をそのまま入力して試せます。そこで使う宣言も一緒に入力してください。長いパイプラインは1行にするか、式全体を括弧で囲みます。`arena { ... }` などのブロックは、閉じ括弧まで続けて入力できます。コンパイルできるかを問う例には、わざと誤りを含めたものもあります。その場合は、表示されたエラーを答えと見比べてください。

`:list` でここまでのプログラムを確認できます。別の例を最初から試すときは `:clear` で入力を消し、残しておきたいプログラムは `:save PATH` で保存してください。入力のたびにプログラム全体をコンパイルして実行するため、同じ出力の表示が省略されても、ファイルへの書き込みなどの副作用は繰り返されます。詳しくはガイドの[「ツールチェーン」](../../guide/ja/16-toolchain.md)で説明しています。

答えに配列が `[2, 4, 6]` とあれば、それは要素の並びを表しています。REPL が表示するのは配列の型で、中身は表示しません。予想を確かめるには `xs[0]` などで要素を調べるか、`xs.sum()` のように一つの値に集計してください。

`fn main` を含むプログラム全体が載っている例は、ファイルに保存して `alignc run file.align` で実行してください。断片からプログラムを組み立てるときは、型や関数の宣言をファイル直下に、実行する文を `main` の中に置きます。
