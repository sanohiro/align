# 11. Do It Until

> 🌐 [English](../11-do-it-until.md) · **日本語**

**Q1.** Align の `for` ループはどこにありますか？

**A1.** ありません。`while` もありません。ここまでの10章では、パイプラインが繰り返しを受け持っていました。

---

**Q2.** パイプラインではなく `loop` が必要なのは、どんなときですか？

**A2.** 入力の各要素を変換・集計するならパイプラインを使います。現在の状態によって次の処理が決まるなら `loop` です。EOF まで読む、失敗した操作を再試行する、推定値が収束するまで計算する、といった場合です。`loop` も式なので、`break` で結果の値を渡せます。

---

**Q3.** ファイルを4096バイトずつ、EOF まで読むには？

**A3.** `loop` を使います。

```align
fn pump(r: reader, w: writer) -> Result<(), Error> {
    mut buf := buffer(4096)
    loop {
        n := r.read(buf)?
        if n == 0 { break Ok(()) }
        w.write(buf.bytes())?
    }
}
```

`loop` は `break` が実行されるまでブロックを繰り返します。ここでは読み込みが0バイトになったら終了します。

---

**Q4.** そこの `break Ok(())` は何をしましたか？

**A4.** ループを終え、その結果を `Ok(())` にしました。`loop` は `if` や `match` と同じく**式**です。ここでは関数の最後の式なので、その値が関数の返り値になります。

---

**Q5.** では、読み込んだバイト数を合計するには？

**A5.**

```align
mut buf := buffer(4096)
mut total := 0
sum := loop {
    n := r.read(buf)?
    if n == 0 { break total }
    total = total + n
}
```

途中までの合計は、ループの*前*に宣言した `mut` の変数に保持します。最後に `break total` で、その値をループの結果にします。

---

**Q6.** Q3 のように、`?` と `loop` は1つの関数で一緒に使えますか？

**A6.** はい。`?` は失敗時に `Err` を返して**関数**から抜けます。`break` は**ループ**から抜けます。抜ける先が違います。

---

**Q7.** `continue` はどこですか？

**A7.** ありません。残りの処理を飛ばして次の繰り返しに進みたいなら、その処理を `if` で囲みます。2つのループを一度に抜けたい場合は、内側のループを関数に切り出します。ループ自体を終えるのは `break` です。

---

**Q8.** `loop` の中で `i` を `0` から `len` まで数え、毎回 `xs[i]` に同じ操作をしています。別の書き方は？

**A8.** `xs.map(...)` で書ける処理です。パイプラインは各要素の処理を、`loop` は繰り返しの制御を受け持ちます。仕様には、この形を指摘する lint が定められています。ただし `alignc` にはまだ実装されていないので、今は自分で確認します。

---

**Q9.** では、関数が自分自身を呼ぶ再帰で、繰り返しを書いてはどうですか？

**A9.** Align は末尾呼び出し最適化を保証しないので、再帰呼び出しごとにスタックフレームが必要になり得ます。スコープ末尾の解放処理や `?` も最適化に関わります。単に1000回繰り返すために、1000回分の呼び出しを積む必要はありません。その場合は `loop` を使います。

---

**Q10.** では、再帰は何のためにありますか？

**A10.** 入れ子の構造を扱うためです。括弧の中にさらに式がある構文や、子ノードも木になっている木構造などです。データの構造に合わせて関数を再帰させると、処理を素直に書けます。

---

**Q11.** パイプライン、`loop`、再帰をどう使い分けますか？

**A11.**

- 多くの要素に同じ操作をする → **パイプライン**（2〜5章）。
- グループごとに集計する → **`group_by`**（10章）。
- EOF、成功、収束などの条件を満たすまで繰り返す → **`loop`**。`break value` で結果を渡す。
- データ自体が入れ子になっている → **再帰**。

---

**Q12.** コードを書かずに、それぞれの処理に合うものを選んでください。

- 配列の全要素を2倍する
- EOF までブロックを読む
- 木のすべての枝をたどる
- 地域ごとの売上を合計する

**A12.** パイプライン、`loop`、再帰、`group_by`。どんな処理かを考えると、使うものを選べます。

---

**Q13.** `0` から `xs.len()` まで数え、`xs[i]` を足すコードがあります。どう書き換えますか？

**A13.** `xs.sum()`。ループで保持しているのがインデックスと途中の集計値だけなら、リデューサで書けることが多いです。

---

**Q14.** `state.done` が `true` になるまで `step(state)` を繰り返します。パイプラインですか？

**A14.** いいえ。既存の要素を順番に処理するのではなく、更新後の状態によって続けるかどうかが決まります。`loop` を使い、状態は `mut` の変数に保持して、最後の値を `break` で渡します。

---

**Q15.** ブロックを読み込み、各ブロックの全バイトを変換します。1つの構文で書きますか？ 2つですか？

**A15.** 2つを組み合わせます。外側の `loop` が「EOF まで読む」を、内側のパイプラインが「各バイトを変換する」を担当します。

---

**Q16.** 関数の中で、失敗し得るパイプラインの結果 `Result` に `?` を付けました。失敗したら、どこから抜けますか？

**A16.** その関数からエラーを返します。ここでは、関数内でパイプライン全体の結果に `?` を付けています。一方、ラムダの中に書いた `?` はラムダから返るもので、呼び出し元の関数から直接抜けるわけではありません。

---

**Q17.** ディレクトリの中にサブディレクトリがあり、その中にもあります。自分でスタックを用意して `loop` でたどりますか？

**A17.** それもできますが、まず入れ子の構造に注目しましょう。再帰関数のほうが構造に沿って書けることが多いです。深さやメモリの上限、たどる順序を制御する必要があるなら、自分でスタックを用意します。

---

> **第十一の戒律**
>
> *各要素の処理にはパイプライン、条件を満たすまでの繰り返しには `loop`、入れ子には再帰。ループを書く前に、パイプラインで書けないか考えよ。*

---
