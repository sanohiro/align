# 13. Four at a Time

> 🌐 [English](../13-four-at-a-time.md) · **日本語**

**Q1.** 2つの配列 `[1, 2, 3, 4]` と `[10, 20, 30, 40]` があります。同じ位置の要素同士を足してください。

**A1.** `zip(a, b).map(fn v { v.0 + v.1 }).to_array()`。`zip` はパイプラインの入力です。2つの配列の同じ位置から要素を取り、各段にペアを1つずつ渡します。

---

**Q2.** CPU は何回の足し算を実行しますか？

**A2.** 4回です。各ペアに対して1回ずつ計算します。

---

**Q3.** それを1回で終わらせることはできますか？

**A3.** はい。CPU が幅の広いレジスタを持っていれば、4つの `i32` を1つの `vec4<i32>` にまとめ、1回の `+` で足せます。

---

**Q4.** どう書けばいいですか？

**A4.** 
```align
v1: vec4<i32> := [1, 2, 3, 4]
v2: vec4<i32> := [10, 0, 30, 40]
v3 := v1 + v2
```
型注釈によって、リテラルがベクトルになります。専用のコンストラクタは要りません。`v3` は `[11, 2, 33, 44]`。1つのベクトル加算で4つの結果が得られます。`v2` のゼロは、次の問題で使います。

---

**Q5.** `v2` で割りたいのですが、ゼロのレーンがあります。どうしますか？

**A5.** スカラーなら、分母を `if` で確認できます。ここではレーンごとに判定したいので、**マスク**を使います。

---

**Q6.** マスクとは何ですか？

**A6.** レーンごとの真偽値を持つベクトルです。`m := v2 != 0` は、すべてのレーンをスカラー `0` と比較します。結果は `mask4<i32>` で、2番目のレーンだけが `false`、残りは `true` です。マスクのリテラルを書く構文はなく、比較から作ります。

---

**Q7.** ゼロ除算を避けるために、それをどう使いますか？

**A7.** `select` を使います。
```align
ones: vec4<i32> := [1, 1, 1, 1]
safe_v2 := select(m, v2, ones)
ans := v1 / safe_v2
```
マスクが `true` のレーンは `v2` から、`false` のレーンは `ones` から選びます。`safe_v2` は `[10, 1, 30, 40]`、`ans` は `[0, 2, 0, 0]` です。2番目のレーンの分母を `1` に置き換えたので、どのレーンもゼロで割らずに済みます。

---

**Q8.** 大きな配列で、この処理を手で書くのは大変ではありませんか？

**A8.** はい。ベクトル化に適したパイプラインなら、コンパイラが自動でベクトル命令を生成できます。`map` で各要素の変換を書けば、ベクトル幅や端数の処理はコンパイラに任せられます。

---

**Q9.** では、`vec` と `mask` を自分で使うのは、どんなときですか？

**A9.** 自動ベクトル化は保証されていません。アルゴリズムが特定のレーン操作を必要とする場合や、計測した結果、手で SIMD を書く効果がある場合に使います。ベクトルとマスクを使えば、その操作を自分で指定できます。

---

**Q10.** `v1` がベクトルのとき、`v1 * 2` は何をしますか？

**A10.** スカラーの `2` が全レーンに適用されます。これをブロードキャストと呼びます。`[2, 2, 2, 2]` と書かなくても、4つの値をそれぞれ2倍できます。

---

**Q11.** `a.max(b)` と `a.max()` の違いは？

**A11.** 引数があれば、レーンごとに2つの値の最大を選び、ベクトルを返します。引数がなければ、全レーンの最大値をスカラーで返します。似た書き方ですが、結果の型が違います。

---

**Q12.** リテラルではなく、配列の連続する4要素をレジスタに読み込むには？

**A12.** スライスを使います。

```align
fn double4(xs: slice<i32>, out dst: slice<i32>, i: i64) {
    v: vec4<i32> := xs.load(i)
    dst.store(i, v * 2)
}
```

`load` は連続する4要素を読み、`store` は4要素を書き込みます。どちらも範囲検査を行います。レジスタ上の値とメモリの間の読み書きは、コードに明示します。書き込み先は呼び出し側の領域なので、`out dst` で受け取ります。5章の `map_into` と同じです。

---

**Q13.** スライスは10要素です。`i == 8` から `vec4` を読み込めますか？

**A13.** いいえ。インデックス8から11までを読もうとするので、範囲検査で異常終了します。4要素ずつ2回処理し、残りの2要素はスカラーで扱います。SIMD でも範囲外の読み込みはできません。

---

**Q14.** マスクを付けるだけで、危険な演算を避けられますか？

```align
select(v2 != 0, v1 / v2, v1 * 0)
```

**A14.** いいえ。割り算は `select` の引数なので、選択の前に、ゼロのレーンも含めて計算されます。Q7 のように先に安全な分母を選び、それから割る必要があります。マスクが選ぶのは結果です。引数の計算を取り消すことはできません。

---

**Q15.** 自分で `vec4` を選ぶと、何を自分で面倒を見る必要がありますか？

**A15.** 処理の幅が4要素に固定されます。別の実行環境では最適な幅が違うかもしれませんし、端数も自分で処理します。SIMD のコードはスライスを受け取る小さな関数にまとめ、呼び出し側や通常の処理は幅を指定しないパイプラインにしておきます。

---

**Q16.** レーンごとに計算してください。

```align
v: vec4<i32> := [1, 2, 3, 4]
w := v * 3 + 1
```

**A16.** `[4, 7, 10, 13]`。`3` と `1` が全レーンに適用され、各レーンで掛け算の後に足し算を行います。

---

**Q17.** `m := w > 8`。どのレーンが `true` ですか？ 残りを `0` にするには？

**A17.** 後ろの2レーンが `true` です。`false` 側には、ゼロを並べたベクトルを渡します。

```align
zero: vec4<i32> := [0, 0, 0, 0]
select(m, w, zero)
```

結果は `[0, 0, 10, 13]`。Q16 の算術演算はスカラーを全レーンに適用しますが、`select` に渡すのは**2つのベクトル**です。`select(m, w, 0)` は型エラーになります。同じ型のベクトルを用意して、レーンごとに値を選びます。

---

**Q18.** 選ばれたレーンだけを合計するには？

**A18.** `w.sum_where(m)` で `23` です。マスク付きの集計なら、選んだ値だけのベクトルをメモリに書き出す必要はありません。

---

**Q19.** 10要素のスライスを、重複なく `vec4` で処理します。4要素ずつ安全に読める開始インデックスは？

**A19.** `0` と `4`。インデックス `8` 以降は端数なので、スカラーで処理します。`load` を書く前に、どのインデックスを読むか確かめましょう。

---

**Q20.** パイプラインか、明示的なベクトル操作かを選んでください。

- 普通の整数1000万個に1を足す
- ハッシュの設計で指定された、固定4レーンの混合処理を1回行う
- SoA の1列を合計する

**A20.** パイプライン、明示的なベクトル操作、パイプライン。まず幅を指定しない書き方を選び、アルゴリズムがレーン操作を必要とする箇所で固定幅を使います。

---

**Q21.** SIMD を手で書いた関数を、ほかのコードからどう呼びますか？

**A21.** 普通のスライスや値を渡します。`vec4` は小さな関数の中で使い、呼び出し側はレジスタの幅を意識せずにデータを渡せるようにします。

---

> **第十三の戒律**
>
