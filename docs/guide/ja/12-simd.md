# 明示的な SIMD ― vecN、マスク、アライメント

> 🌐 [English](../12-simd.md) · **日本語**

まずはスライスや SoA の列に対するパイプラインを使います。コンパイラは、ターゲットに合った幅でベクトル化できます。固定幅でレーンごとの処理を指定したいときに `vecN<T>` を使います。

## `vecN<T>` ― 値としての SIMD レジスタ

```align
fn main() -> i32 {
    a: vec4<i32> := [1, 2, 3, 4]
    b: vec4<i32> := [10, 20, 30, 40]
    c := a + b          // lane-wise addition: [11, 22, 33, 44]
    d := c * 2          // scalar broadcasts across lanes
    print(d[2])         // 66 — lane read (constant index)
    print(c.max())      // 44 — horizontal reduction
    return 0
}
```

数値スカラー型に対して、`vec2`、`vec4`、`vec8`、`vec16` の SIMD ベクトル型があります。算術演算はレーン単位で行い、機械語の命令数は演算とターゲットによって変わります。スカラー値は全レーンにブロードキャストされます。`v[i]` でレーンの値を読み、`mut` のベクトルなら `v[1] = 99` のように書き込めます。

`a.min(b)` と `a.max(b)`、浮動小数点演算の `sqrt`、`abs`、`floor`、`ceil`、`round`、`trunc` は、レーンごとに適用されます。また、内積を計算する `dot(a, b)` と、丸めを1回だけ行う融合積和演算の `fma(a, b, c)` があります。

整数レーンの演算規則はスカラーと同じです。オーバーフローはラップし、ゼロ除算ではプログラムがアボートします。どのレーンでも未定義動作にはなりません。

## マスクと `select` ― レーンごとに選ぶ

ベクトル同士の比較結果は `maskN<T>`（マスク型）になります。これは `if` のような制御フロー（分岐）としてではなく、データ（ブレンド用のフラグ）として使用します。

```align
fn main() -> i32 {
    scores: vec4<i32> := [90, 45, 82, 60]
    m := scores > 80                        // mask4<i32>: [t, f, t, f]
    picked := select(m, scores, scores * 0) // lane-wise blend, no branch
    print(picked.sum_where(m))              // 172 — masked reduction: 90 + 82
    return 0
}
```

`select(mask, a, b)` は、マスクに応じて各レーンの値を `a` または `b` から選びます。`v.sum_where(mask)` は、マスクが `true` のレーンだけを合計します。パイプラインの `xs.where(p).sum()` でも、条件を満たさない要素を加算の単位元である 0 に置き換えることで、分岐なしの集計ができます。

`select` がレーンを選ぶ前に、値の引数は両方とも評価されます。レーンごとの `if` ではありません。`select(d != 0, n / d, zero)` と書いても、分母がゼロのレーンで割り算が実行されます。先に演算の引数を安全な値にし、その後で必要な代替結果を選びます。

```align
fn main() -> i32 {
    numerators: vec4<i32> := [12, 20, 30, 40]
    denominators: vec4<i32> := [3, 0, 5, 0]
    ones: vec4<i32> := [1, 1, 1, 1]
    zero: vec4<i32> := [0, 0, 0, 0]
    valid := denominators != 0
    safe := select(valid, denominators, ones)
    quotients := select(valid, numerators / safe, zero)
    print(quotients.sum())    // 10: 4 + 0 + 6 + 0
    return 0
}
```

最初の選択で不正な割り算を防ぎ、2回目で「分母がゼロなら結果をゼロにする」という方針を実現しています。`select` には同じ型のベクトルを2つ渡します。算術演算と違い、スカラーの代替値を自動で全レーンに適用することはありません。

## メモリとレジスタを橋渡しする ― `load` / `store`

```align
fn scale_add(xs: slice<f64>, ys: slice<f64>, out dst: slice<f64>) {
    x: vec4<f64> := xs.load(0)      // 4 lanes from the slice, bounds-checked
    y: vec4<f64> := ys.load(0)
    dst.store(0, x * 2.0 + y)       // scale and add all 4 lanes
}

fn main() -> i32 {
    xs := [1.0, 2.0, 3.0, 4.0]
    ys := [10.0, 10.0, 10.0, 10.0]
    mut out := [0.0, 0.0, 0.0, 0.0]
    mut d: slice<f64> := out
    scale_add(xs, ys, d)
    print(out.sum())                // 60.0
    return 0
}
```

`s.load(i)` は、スライスから N 個の連続する要素を SIMD レジスタに読み込みます（N はベクトルの型注釈から推論されます）。`s.store(i, v)` は、計算結果のベクトルを `out` スライス越しにメモリへ書き戻します。これらの操作はどちらも実行時に境界チェック（Bounds Check）が行われます。この `load`/`store` のペアこそが、手書きのカーネルが配列を走査する際の基本形です。通常は `chunks(N)` で処理を進め、最後に N に満たない端数要素をスカラー処理で片付ける、というパターンになります。

10要素を `vec4` で重複なく処理するなら、4要素を読める開始位置は `0` と `4` です。`8` から読むとインデックス `11` まで必要になり、範囲検査で失敗します。`8` と `9` はスカラーで処理します。読み込んだ後にマスクを付けても、範囲外の読み込みは正当化できません。

## `align(N)` ― ロードをアライメントさせたいとき

`align(64) xs := [...]` は配列の領域を64バイト境界に揃えます。`align(64) CacheLine { ... }` は構造体を同様に配置し、配列内の要素間隔もそれに合わせます。コンパイラがロード位置のアライメントを証明できれば、その情報をベクトルロードに使えます。FFI で共有するバッファでは `layout(C)` と組み合わせられます。効果は小さいため、適用する前に計測してください。

## 二層のルール

- **第1層（デフォルト）：パイプライン。** `xs.map(f).where(p).sum()` のような処理、SoA 列への操作、`group_by` などを指します。これは SIMD の幅に依存しません。コンパイラがターゲット・アーキテクチャに合わせて最適なレーン数を選択し、同じソースコードから AVX2、NEON、あるいはスケーラブルなベクタ ISA 用に自動ベクトル化を行います。この層は、あなたのデータサイズやハードウェアに自動で追随してくれます。
- **第2層：`vecN` / `maskN`。** 内積、FIR フィルタ、ブレンド処理などで、固定のベクトル幅とレーンごとの操作を指定したい場合に使います。

> **最適化:** 第1層のベクトル化はターゲットとプロファイルに依存し、言語上の保証でも、固定のバイト数を境にした規則でもありません。ループを安全に変換できるかどうかや、入力の形にも左右されます。判断は `alignc explain-opt`、生成されたベクトルの幅は `emit-llvm --stage optimized` で確認できます。

明示的な SIMD は、上の `scale_add` のようにスライスを引数とする小さな関数にまとめます。そうすれば、呼び出し側はベクトル幅に依存せずに済みます。書き始める前に、パイプラインが生成するコードを `alignc emit-llvm --stage optimized` で確認してください。`<4 x i64>` のようなベクトル型から、ベクトル化された箇所が分かります。パイプラインを置き換える前に、速度を比較します。
