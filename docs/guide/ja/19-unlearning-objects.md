# 19 — オブジェクト指向から考え方を切り替える

> 🌐 [English](../19-unlearning-objects.md) · **日本語**

Java、C#、Python などから来た人は、相互にやり取りするオブジェクトでプログラムを組み立てることに慣れているかもしれません。Align にはクラスや継承がなく、データと、それを処理する関数を分けます。

本章では、オブジェクト指向でよく使うパターンを Align でどう表すかを見ていきます。

## 1. 多くの要素のフィールドを更新する

**OOP のアプローチ:** 
自身の `health`（体力）や `x`, `y` 座標を持ち、自らの状態を更新する `update()` メソッドを備えた `Player` クラスを作ります。

**Align のアプローチ:**
データと処理を分けます。この例では、1人の `Player` を更新するより、座標の列をまとめて更新する形で考えます。

```align
Player { x: f64, velocity_x: f64, health: i64 }

// Player オブジェクトを1つずつ更新するのをやめる:
arena {
    rows := [
        Player { x: 0.0, velocity_x: 1.0, health: 100 },
        Player { x: 5.0, velocity_x: -1.0, health: 80 },
    ]
    players := rows.to_soa()

    // すべての「次の座標」を、キャッシュフレンドリーな1回のパスで一括計算する
    xs := players.x
    vxs := players.velocity_x
    next_x := zip(xs, vxs).map(fn v { v.0 + v.1 }).to_array()
}
```

## 2. 複数の種類のデータを処理する

**OOP のアプローチ:** 
`Shape` インターフェースのリストに `Circle`、`Rectangle`、`Triangle` を格納し、各要素の `shape.area()` を呼びます。呼び出しには仮想ディスパッチが必要です。オブジェクトがメモリ上で離れた場所にあれば、走査時のキャッシュミスも増える可能性があります。

**Align のアプローチ:**
要素の数が少なく種類が混ざっているなら、直和型（Sum Type）を使います。あるいは処理速度を最優先するなら、配列そのものを型ごとに分離します。

もし混ぜて保持する必要があるなら：
```align
Shape { Circle(f64), Rect(f64, f64) }

shapes := [Shape.Circle(2.0), Shape.Rect(3.0, 4.0)]
areas := shapes.map(fn s {
    match s {
        Circle(r) => 3.14159 * r * r,
        Rect(w, h) => w * h,
    }
}).to_array()
```
種類ごとに処理できるなら、Circle を `soa<Circle>`、Rect を `soa<Rect>` に分けます。それぞれのパイプラインは1種類の図形だけを扱うため、種類を判定する分岐が不要になります。

## 3. コレクションのメモリを確保する

**OOP のアプローチ:** 
ループの中でリストに要素を `append` していきます。リストは自動的に自身のサイズを拡張し、予測不可能なタイミングでヒープメモリを確保（アロケーション）します。

**Align のアプローチ:**
同じ期間だけ使うデータには `arena` を使います。ブロックを抜けると、メモリをまとめて解放します。一括変換では、結果の蓄積をパイプラインに任せ、終端でメモリ確保を明示します。

```align
threshold := 100
arena {
    readings := [42, 150, 88, 203]
    // 確保はパイプラインの終端に1つだけ — 隠れた成長はない
    spikes := readings.where(fn r { r > threshold }).to_array()
} // ズドン。すべて消え去る。
```

長さの分からない入力を逐次 I/O で受け取る場合は、`array_builder<T>` の `.push()` で蓄積します（第 [18](18-std-services.md) 章）。変換全体をパイプラインで表せる場合は、パイプラインを使います。

## 4. フィールドを読み、データを変換する

**OOP のアプローチ:** 
フィールドを直接公開せず、`get_health()` や `set_health()` で状態へのアクセスや更新時の処理を制御します。

**Align のアプローチ:**
Align の構造体のフィールドは公開されています。データを変換するときは、構造体を受け取り、新しい値を返す純粋関数を書きます。フィールドを読むだけで別の処理が実行されることはありません。

## まとめ

Align では、処理に必要なデータと、それに行う変換から考えます。フィールドを連続した列にまとめると、それぞれのパイプラインが必要なデータを順に処理できます。
