# Streaming std.compress through existing reader and writer handles

The caller can transcode a file, pipe or buffered stream without materializing input or output in an Align buffer. Whole-buffer transforms retain their allocation and atomic-output contracts. The preset-dictionary capability precedes this surface.

| Surface | Public record, owner and verification |
|---|---|
| Calls | For each format gzip, zlib, deflate_raw, zstd, add compress.<format>_compress_to(source: reader, destination: writer, level: i64) -> Result<i64, Error> and compress.<format>_decompress_to(source: reader, destination: writer, max_bytes: i64 = 1073741824) -> Result<i64, Error>. For each dictionary-capable format an optional last dictionary: bytes is admitted after the explicit level or cap. Gzip rejects it. The return counts output bytes accepted by destination, including bytes in its write buffer; every call is Impure. |
| Argument lifetime | Evaluate the reader, writer, numeric argument and optional dictionary once in order. Require the same receiver forms as io.copy: live bound reader/writer or unbuffered standard stream. Reject unbound owned/buffered handle expressions; the argument rule follows io.copy if that rule changes in the future. Borrow the I/O handles and dictionary only for the call. Do not close the handles, flush the writer, rewind the reader, or retain the dictionary. From evaluation through the native call, pin each reader/writer and its fd owner against move, replacement, or destruction by a later argument; static rejection covers each owner and borrowed connection in both frontends. Direct unbuffered std streams allocate a wrapper object; own its temporary cleanup exactly once on success, native error, or early exit of a later operand, leaving its borrowed fd open. A non-fallthrough argument prevents the native call. Use existing Result<i64,Error> drop and branching and the existing byte-view cleanup for dictionary temporaries. |
| Validation and state | After every source operand finishes, check level (0..9 or 0..22) or cap (any nonnegative i64, inclusive), with the existing hard-error policy for violated numeric preconditions. Extended caps are possible because the output is streamed. Check numeric arguments first, then null reader or writer (Invalid), dictionary shape (nonempty gzip or null with a positive length is Invalid), width and trained header. Allocate bounded staging (refusal returns Invalid as in io.copy), then initialize native state and apply level/dictionary under the one-shot contract before the first read. Upstream may build tables lazily on its first compression step; classify that failure with its normal engine mapping, and document that it may follow the first read. Verify zero cursor advance for all earlier ordinary failures. Any native context acquired is freed exactly once even after setup, I/O or engine errors. Never publish a result count on failure. |
| Framing | Encoding consumes to EOF and writes exactly one complete member/frame including for empty input. Decompression requires complete input to EOF; zlib/raw require one stream, gzip accepts complete RFC 1952 members, zstd accepts only complete RFC 8878 and skippable frames. Reject empty, corrupt, truncated and trailing input. Validate multi-byte magic across window boundaries using at most four explicit stack bytes. When a provider fills the output grant, continue draining its pending output with the unconsumed input or empty input before reading again. Empty-input no-progress while expecting additional input permits refill; no-progress with supplied input and writable output is Invalid. At EOF drain pending output and require an ended frame before success. An encoder finalizes with repeated finish calls until frame completion or a mapped engine error. Apply the same dictionary to each frame. Reject old zstd frame formats regardless of provider build. At the inclusive cap continue through trailers and empty/skippable data using a one-byte output probe. |
| I/O and failure | Consume already-buffered input lookahead in order. A read can advance the underlying stream by one input window past the byte at which a later decode/write error is observed. The call never rolls back. It uses the ordinary writer path, including buffering, connection-derived TCP writer signal suppression, and short-write/EINTR handling. Generic-fd writers (including redirected stdout) inherit the existing process signal disposition. On success or error the handles follow their existing cursor/buffer contracts. Input, output and provider ordinary failure statuses use existing io.copy/codec Error mappings. Check native errors before same-step cap or output-count overflow, then cap, then write the successfully produced span. Never give the writer bytes past the cap; earlier output may already be visible when validation of a later trailer or frame fails. Limit each output grant to the remaining allowance so independently accepted prefixes can reach the inclusive cap. For encoding, exceeding representable i64 byte count returns Invalid before writing the excess. |
| Storage and cost | One bounded input window (borrow buffered lookahead where possible) and one bounded output window, each at most 64 KiB of payload, plus four stack bytes for framing lookahead and one stack byte for the cap probe, independent of total bytes. No growing payload Vec and no spool file. Native codec workspace and the caller-owned reader/writer/dictionary storage are separate costs. Use the stable streaming provider APIs. Preserve preexisting aligned buffer and socket output paths. A local large-stream measurement records maximum wrapper staging memory and throughput; it also checks an input larger than the staging windows and exact decoded output count. |
| Compiler and ABI | One closed HIR/MIR stream transform records format, direction, the two typed handles, numeric operand and optional byte view. Validate discriminator, shape, native closure and every operand before per-unit summary/admission. New keys align_rt_compress_<format>_<compress/decompress>_to use i64(ptr reader,ptr writer,i64 level_or_cap,ptr dictionary,i64 dictionary_len); omitted dictionary uses (null,0), including gzip. Return sign encoding of io.copy. Foreign/Unstated, pointer arguments 0,1,3 escape conservatively. Match frontend/generic template analysis, lifetime/effects, codegen golden, structural hash and runtime inventory; sync draft, language digest, open decisions, std-design/compress and Japanese mirror. Whole/warm per-unit and mixed format programs must use only existing libz/libzstd capability dependency. |
| Native pump | The existing reader owns lookahead. A single sequential pump supplies each bounded input slice to the engine and writes each accepted bounded output before requesting a refill. Track input position, whether a frame completed, and whether full output requires draining. A zlib z_stream has a stable address for its entire initialized lifetime: construct it in its final stack slot before init and let a guard borrow that slot through end. Zstandard's allocated context is stable by opaque pointer. On finishing an encoder use Z_FINISH or ZSTD_e_end repeatedly until native completion. A gzip decoder resets only after a complete member and encountering the next input. A zstd decoder validates each new ordinary/skippable magic (four bytes even across refill boundaries) and passes those same bytes to the ongoing decoder; it preserves a configured dictionary across frames. At a terminal libz/raw boundary verify actual EOF and reject further bytes. |
| Structural closure | Share the source/handle place checks with io.copy, add the numeric/dictionary checks from the one-shot codecs, and authenticate those same children and types before emitting MIR or publishing a unit. All operations have one closed format/direction discriminator; preserve capability selection in whole/Thin/module/REPL final link. Use the standard count-or-status result and schedule direct stdin/stdout wrapper cleanup for success, error, argument non-fallthrough and nested block exits; an owned file wrapper and its connection loan stay live through later arguments. Forged HIR or MIR with swapped handles, invalid dictionary shape, numeric width, unattached producer, or wrong result must fail validation when unused. Native cleanup, consumed-reader cursor and partial written bytes are covered independently of source admission. Owner paths cover existing gzip/zstd, one-shot dictionary and I/O copy regressions. |
| Capability boundary | Keep the source transform, pump, error contract, native callbacks and checked compiler lowering together because each dormant piece would require the same lifetime and framing proof twice. Four codecs share one I/O and partial-publication domain; the prior dictionary PR closes independent whole-buffer configuration. The full matrix can exceed 1,000 hand-written lines including format-interoperability and failure tests. A format-free or input-only half cannot exercise actual EOF, writer error or native cleanup. |
| Acceptance | Normal real programs with buffered and unbuffered files/std handles, pipe short reads, preexisting lookahead and prepopulated buffered writer. Independent provider interoperability for all four formats and each dictionary form, cap=0/exact/one short including a later empty/skippable frame, failed later checksum after output publication, trailing garbage, sparse/trained dictionaries. Split every multibyte header/trailer at a chunk boundary; exercise EOF while a decoder still has pending output. A closed TCP write peer verifies signal suppression. Injected read/write faults and a refill that fails after a full output grant check for delivered pending bytes, cursor progress, mapped error and exactly one provider cleanup. Count standard stream wrappers on all exits. Whole/warm unit, invalid type/arity/handle temporaries, moved handle, post-call reuse, discarded result, branch and ? forwarding. |

## Implementation and measurements

Each provider owns its native context and Drop. The statically dispatched I/O loop retains independent libz and libzstd link closures. A gzip-only and a Zstandard-only executable both link under their ordinary capability. Native split-window fixtures cover independent frame bytes, repeated members, malformed late checksums, dictionary configuration before I/O, EOF, bounded writes and output delivery before a failed refill. The existing closed-peer TCP test exercises this writer route with the process SIGPIPE disposition at its default. The checked-HIR and MIR signature matrices reject malformed operations before whole-program and partition lowering. The imported source owner builds both ways and repeats with a warm separate-unit cache. A Linux linker observer counts one allocation and one release of each direct standard-stream wrapper on normal completion, native error and a return from the level expression. The same observer pairs each acquired native context with its release after success, dictionary setup failure, invalid frames, and failed descriptor I/O. Encoder tests check zlib dictionary identity, the trained Zstandard frame ID, and dependence on the supplied history.

A local x86_64 run streamed 16 MiB through files, alternating 32 KiB of deterministic pseudorandom data with 96 KiB of repetitive text. Each Align stream was decoded by Python zlib or ZSTD_decompress; each independently encoded stream returned the same SHA-256 and byte count through Align. One wall-clock run, including process and file I/O, measured the following rates. These observations impose no throughput requirement.

| Format at level 3 | Encode MiB/s | Decode MiB/s |
|---|---:|---:|
| gzip | 237.9 | 1060.4 |
| zlib | 243.0 | 1042.9 |
| raw DEFLATE | 253.0 | 1349.7 |
| Zstandard | 1498.0 | 1856.9 |

The thread-local Rust allocation owner measured 131072 requested bytes for unbuffered input and 65536 with an existing input window at both 1 byte and 16 MiB. This measures wrapper heap requests during the operation; the stack prefix and cap probe, native C workspace, existing reader/writer storage and RSS are separate.
