# Dense borrowed bit sets

The four-word expert mask in align-llm/src/native_cuda_moe.align uses division, shifts and read/modify/write operations to read and set up to 256 flags. The SIMD and SoA layout already ships. The existing core.codec bool column uses the same LSB-first packed byte convention. No packed SoA producer currently has a demonstrated bandwidth requirement. This capability supplies a dense view usable by the existing program independently of that layout decision.

| Contract | Record and closure owner |
|---|---|
| Names | The reserved builtin type spelling is bitset, without generic arguments and under the ordinary builtin type collision rules. The value namespace bitset for the constructor requires explicit import core.bitset and uses the standard builtin module name. No second qualified type spelling. bitset.view(storage: slice<u8>, count: i64) -> bitset. The type is a non-owning Copy view. A caller with words can pass a slice of the words through its existing as_bytes() operation. Read b[i] -> bool, assign b[i] = value where value: bool, b[lo..hi] -> bitset with omitted bounds following slice syntax, b.len() -> i64, b.count() -> i64, b.any() -> bool and b.all() -> bool. No default constructor, implicit packing or user allocator. All work is Pure except effects in child expressions or mutation of captured/external storage under the ordinary language rules. |
| Formation | Evaluate storage then count once; guard the earlier storage generation through later operands. If count < 0 or ceiling(count/8) > storage.len, abort with the construction precondition before deriving addresses or reading bytes. Compute the ceiling as quotient plus a nonzero-remainder bit, avoiding count+7 overflow. Additional bytes in storage are ignored and untouched. Zero accepts empty storage. Every starting byte alignment is valid. The bit at logical i is bit i%8 of byte i/8, low bit first; this convention is independent of native endianness. A final partial byte can contain any high bits. Do not require or clear zero padding. |
| Operations | Reads and windows complete the descriptor before the index or range bounds, left to right. For assignment require the same stable local or admitted field place as ordinary slice stores. Evaluate index, then RHS, then load the current destination header and check bounds before the read/modify/write. An RHS that legally rebinds a local descriptor selects the new backing and its current write authority. A terminal index or RHS prevents the later work. Index and provided bounds use i64, with the usual contextual integer literals. Require 0 <= i < length for access and 0 <= lo <= hi <= length for ranges; invalid access hard-aborts before payload access. A slice keeps the source generation and current authority. For a record field holding a view, bind its projection to a mutable local before assigning individual bits, as with ordinary slice fields. For a nonempty view normalize to (first touched byte address, head bit in 0..7, logical count). Compose byte displacement as lo/8 + (lo%8+head)/8; never add head to a full-width i64 index. For count n>0 the exact readable span has 1+(n-1)/8+(head+(n-1)%8)/8 bytes; never add head+n in signed arithmetic. For empty, retain root provenance and use parent base, offset 0 and length 0 without pointer arithmetic. A write updates one byte and preserves all bits outside the target mask. |
| Terminals | All terminals are total on a valid view. Empty has len=count=0, any=false, all=true. Mask both ends correctly even if they share a byte. Any widened payload load requires its complete byte span be inside the represented storage and uses alignment 1. Count uses LLVM ctpop for full bytes/words; bounded tail processing does not depend on padding beyond the last byte. All and any may stop as soon as determined. O(1) descriptor and temporary space, zero heap payload allocations, count O(ceil(count/8)); bounds, len and single-bit access O(1). No timing or target-instruction guarantee. Guard-page end/start, all bit offsets, short and multiple-word ranges, dirty tail, empty and high-limit descriptor arithmetic are resource/safety owners. |
| Aliasing | Treat the descriptor exactly as a slice<u8> for recursively carried view lifetime, owner generations, invalidation by replacement/growth/move/drop, region return facts, shared/exclusive call authority and descriptor rebind downgrade. Construction and local windows preserve writable authority when the source has it. Only owning/exclusive authority can assign to a bit; an ordinary function-returned descriptor, a by-value parameter or captured view is read-only. Direct out bitset is rejected, consistently with the existing out slice<T> formation rule. A bitset.view over a caller-initialized out slice<u8> is readable and writable under the normal slice authority, including the byte read required by assignment. Ordinary mutable-access projection checks apply to nested records, sums and tuples. Writes invalidate derived validated observations of the touched backing with the ordinary byte alias rules. Overlapping disjoint logical bits in a common byte are a physical alias for any write. A bit update is a Read+Write of the whole addressed byte. Resolve bitset/bitset, bitset/byte slice and bitset/word slice footprints to the same backing. Unknown footprints conservatively overlap. Publication through spawn, par_map or an indirect call must preserve the existing reader/writer exclusion for the physical backing. Distinct proven storage can be used independently. No atomic bit operations. |
| Transport | The nominal bitset leaf participates in the existing structural borrowed-view and return-region analysis. The closed RegionPlain deep-construction bound retains its enumerated leaf types. Type formation includes generic instantiation, records, tuples, enum/Option/Result carriers, ordinary function results and function values. For collections and task payloads apply the same formation, authority and escaping restrictions as an embedded slice<u8>; do not open currently rejected containers via generic reconstruction. Bitset is distinct from slice<bool>, contains no Drop state, may not enter the existing primitive native scalar ABI, raw load/store, JSON/codec wire schema or new SoA field layout. Native function-value parameters/returns, captures, inlining, whole and per-unit compilation use one LLVM descriptor { ptr, i64 head, i64 len }, natural pointer/i64 alignment, 24 bytes on supported 64-bit targets. The 16-byte ptr/len header fast paths do not apply. Value parameters and results transport the complete descriptor; explicit borrows of addressable descriptors use the ordinary borrowed-parameter pointer ABI. Direct named helpers may return a region-inferred read-only descriptor. A function value may accept a bitset with the ordinary view parameter modes; direct bitset returns through function values follow the same rejection as bare slice returns. For Option<bitset> or Result<bitset,Error>, reuse the existing aligned union/tag layout with a 24-byte, align-8 payload; enclosing product/union layout recomputes actual offset, stride and padding. Exclude whole collections of bitset leaves, chunk-of-bitset, box<bitset>, native raw calls and layout(C) by-value records recursively containing a bitset. Ordinary Align records and their already-admitted containers may carry a nested view under existing complete-graph region rules. A task may capture a shared view while the scope pins its backing, with the same restrictions on capture, consumption, returned data and exclusion as for slices. No external FFI exposure or runtime ABI key. Use canonical_graph one-byte leaf tag 84 (Ty) and 64 (Scalar), with no payload. The interface type is IType::Named {path: bitset, args: []}; its independent record bytes are 00 06 00 00 00 62 69 74 73 65 74 00 00 00 00. Existing return borrow and region roots keep their discriminators, ordered indices and width; changes to shared/mutable root summaries invalidate cached imports even with an identical source signature. Unrecognized/mismatched cached records fail closed before materialization. |
| Compiler boundaries | Name/type resolution, type walkers, type-holding scalar and aggregate descriptors, borrow-root and generation tracking (including early returns, ?, map_err, if/match/loop joins), writable projection proof, write effects, indirect call reborrows, closure/task capture and cleanup inherit the byte-slice policy. HIR authenticates constructor, range/index/assignment, terminals and every result, including dead expressions. MIR carries typed operations with exact operand kinds, descriptor origin and destination write proof. A byte-slice reinterpretation, arbitrary aggregate constructor, non-dominating or partial-predecessor guard and inconsistent lane fields cannot manufacture a descriptor or authorize memory access. Checked constructor/window/access operations in MIR define and dominate payload addressing on every reachable predecessor. Validate a forged constructor, returning a mutable alias of a shared view, stale proof, window type, wrong bound/result, uninitialized out and wrong index-store authority in whole and partition admission before generating memory operations. No heap ownership or native cleanup transfer. |
| Evidence | Run a 256-flag source with actual borrow [i64;4] and borrow mut [i64;4] helper boundaries on supported little-endian targets, including bits 63, 64 and 255 with reads, set, clear and window count; compare byte-for-byte with an independent scalar reference across offset 0..7, dirty padding and every short length. Validate unwrap, match, early returns and owner loss/replace, captured task and aggregate escape, writable and read-only call modes, foreign-element, pointer alignment and forged-HIR/MIR negatives in both compilation modes, including a warm imported unit and a function-value call. Validate post-RHS rebinding to distinct storage, downgrade to a read-only destination, terminal RHS before bounds, overlapping bit/byte/word or task views, UTF-8/codec observation invalidation, guard-page ends, no allocation in local bit transforms and popcount in unoptimized LLVM. Verify independent type-tag and interface vectors, wrong/truncated tags, wrong root indices, same-signature cold/warm change to only the returned/write root, head=7 exact guard-page bounds, and mathematical near-i64-max spans without constructing unusable backing. Future packed SoA projects a bitset view using this layout. Private matching packed codec fixtures are only an independent layout check. Existing SoA/JSON/DB/CSV layouts retain their established bytes. Benchmark only the explicit bounded-space/linear-resource claims, not a relative throughput promise. |
| Ownership | Compiler sema/HIR/MIR/LLVM and interface producers own this intrinsic. Synchronize draft memory/layout and library sections, language digest, settled decisions, design notes, M6 roadmap, core-design bitset, vec-mask and hash English/Japanese and capability status. Constructor, region proofs and bit operations ship together; each requires the same descriptor and storage proof so an independently dormant representation PR would repeat that work. The cross-stage exhaustive type sweep plus admission and alias tests can exceed 1000 hand-written lines. |
