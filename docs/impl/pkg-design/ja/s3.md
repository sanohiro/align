## 機能境界

最初の機能は、明示的な認証情報・endpoint・時刻・request データから S3 SigV4 の
Authorization header 付き `http_request` を作る。結果は呼び出し側の既存
`http_client.request` / `request_stream` に渡せる。GET・HEAD・PUT・DELETE・bucket
query・provider 固有 header はすべてこの経路を使う。AWS の操作/schema SDK ではなく、
署名と request 構築を提供する。

canonicalization は package、暗号は `std.crypto`、transport・TLS・pool・framing・
timeout・response 所有権は `std.http` が担当する。virtual-hosted / path-style は、
呼び出し側が実際の origin と未encode の絶対 path を指定して選ぶ。例えば
`https://bucket.s3.us-east-1.amazonaws.com` と `/key`、または
`https://s3.us-east-1.amazonaws.com` と `/bucket/key`。bucket 名推論、endpoint 探索、
認証情報の file/environment 検索、時計読み取り、credential refresh、redirect 追従、
package retry は行わない。

一つの vendor 可能 subtree `apps/s3/pkg/s3.align` が `pkg.s3` と signer 全体を提供する。
canonicalization・署名・HTTP 構築を、未利用の中間 producer PR に分割しない。
wire/negative owner を含めて手書き 1,000 行を超える場合も、署名と送信 bytes の一致を
一つの境界で検証する方が、中間文字列を別々の public seam にするより統合リスクが低い。

source probe では transport 前提も見つかった。この機能以前の HTTP は `.body(empty)` または
`post(url, empty)` を明示しても Content-Length を省略するが、S3 PUT はこれを必要とする。
既存 request owner/view に body の存在を保持し、明示的な空 body には `0` を送る。
この一般 HTTP 規則を signer と同時に実装する。S3・host・method・署名 header に依存した
特例は設けない。

## 正式な公開契約台帳

以下の表と V/W 規則が厳密な契約を共同で所有する。省略可能な引数や default はない。
呼び出しは引数を source 順に一度ずつ評価し、その後に検証する。

| 公開宣言 | 入出力の意味 | 所有権・allocation・effect | owner・identity・前提・受入 |
|---|---|---|---|
| `pub Credentials { access_key: str, secret_key: slice<u8>, session_token: Option<str> }` | field 順はこの通り。`None` は session header なし、`Some` は明示 token。V2 で検証し、有効期限や provider を推論しない。 | 通常の source root を保持する Copy descriptor。allocation/secret owner なし。入力は `request` 完了まで生存し、結果は借用しない。 | nominal package record。順序付き到達 field 定義と imported borrow summary が interface/cache identity に入る。C1/V1。 |
| `pub Endpoint { origin: str, region: str }` | この field 順で HTTP origin と SigV4 region を指定、V3。service は常に `s3`。 | Copy 借用 descriptor、allocation なし。 | 通常 source/interface owner。V1/W1。 |
| `pub Field { name: str, value: str }` | この field 順。query/header は同じ pair 型の別々の入力 slice で、V5/V6・W2/W3 に従う。 | Copy 借用 descriptor。slice/field を変更・保持しない。 | nominal owner。C1/V1/W1。 |
| `pub fn request(credentials: Credentials, endpoint: Endpoint, method: str, path: str, query: slice<Field>, headers: slice<Field>, body: slice<u8>, now_ns: i64) -> Result<http_request, Error>` | 成功は独立所有の署名済み request。package 入力拒否は V1–V7 順の `Error.Invalid`。wire は W1–W5。network status は変換しない。 | 既存 FFI hash/HMAC により Impure。入力は call 中だけ借用。結果は method/URL/header/body の copy を所有し、credential/field/arena/body/endpoint の root を保持しない。builder/encode 文字列/digest array は全 exit で Drop。既存 allocation/crypto failure は hard failure。 | 通常 package source。builtin/checked opcode/native ABI/compiler type/cache schema の追加なし。HTTP 所有型 #998、time/path encoding #996、hash/HMAC、Copy record slice、builder、借用 aggregate root と同一機能内 H1 が前提。C1/V1/W1/I1。 |
| 既存 `http_request.body(data)` と `http_client.post(url, body)` の明示 body framing | setter は空入力でも present にし、replacement 後も present。`post` も present。fresh request、`get`、`get_many` は setter 前は absent。present の場合だけ現在の長さ（0 を含む）の Content-Length を出す。presence を消す setter はない。 | input copy/borrow、Move/nulling/Drop、transport/error は既存のまま。owner/view に private bool を追加し、allocation/外部 ABI field は増やさない。 | runtime の構築/view/serializer が owner。HTTP method 特例や compiler 変更なし。H1/W1。 |

package persisted format、reflection table、runtime secret registry、signing-key cache はない。
通常の source/interface/dependency implementation hash が whole/per-unit artifact/cache を決める。
record identity は nominal。既存 module-wide capability 規則により HTTP・time・encoding・
libcrypto row を保持する。中間 secret 文字列/digest array は既存 Drop を使い、zeroization
保証はない。credential/signature を含む log/diagnostic は出さない。

## 決定的な検証

V1–V7 は package allocation・hash/HMAC・request 構築・header setter より前に完了する。
不正入力は HTTP header abort を起こさない。すべて `Error.Invalid` だが、この順序で
無処理境界も固定する。上限は provider 制限でなく package の受入制限。長さは byte、
境界は inclusive。加算/乗算は検証済み有界値で行い、wrap しない。

1. **V1 件数/サイズ:** `query.len() <= 128`、`headers.len() <= 120`、
   `body.len() <= 1073741824`。空 query/header/body は有効。
2. **V2 認証:** access key は 1–256 bytes、ASCII 英数字/`-`/`_`。
   secret は 1–4096 bytes、NUL を含む任意 bytes。token は `None` または
   1–16384 bytes の `Some`、各 byte は ASCII `0x21..0x7e`。空 Some、空白、NUL、
   非 ASCII は拒否。access、secret、token 順。認証情報の真正性は server が判断。
3. **V3 endpoint:** origin は 1–1024 bytes。厳密な小文字 `http://` または
   `https://` の後に非空 authority。path/query/fragment/userinfo/percent escape/
   空白/非 ASCII を許さない。非 bracket host は ASCII 英数字/`.`/`-`/`_` のみ、
   後に optional `:port`。bracket host 内は hex digit/colon/dot のみで colon を一つ以上
   含み、その後は optional `:port` のみ。host の表記/大小文字を保持する。
   port は十進 1–5 桁、値 1–65535。先頭 zero を許し保持する。これは字句検証であり、
   DNS/IP 存在や完全な address 妥当性は送信時の transport error。region は
   `[a-z0-9-]{1,64}`。origin、region 順。
4. **V4 method/path:** method は 1–32 文字の大文字 ASCII 英字。path は `/` で始まる
   1–8192 UTF-8 bytes。その後の NUL/`?`/`#`/`%`/連続 slash/dot segment も encode 対象の
   data として扱い、既 encode URL 解釈や正規化はしない。method、path 順。
   API 固有 method/body/key 制限は server が所有。
5. **V5 query:** source 順に name 長 1–1024、value 長 0–8192 を検証。
   どちらも UTF-8 data、NUL は percent encode。空 value、重複 name/pair を保持し、
   既 encode escape を解釈しない。第二の query 認証モードを排除するため、ASCII
   case-insensitive で `x-amz-` から始まる name を拒否する。`list-type`、`prefix`、
   `continuation-token`、`versionId`、`uploads` 等は data であり API registry ではない。
6. **V6 header:** source 順に name 長 1–256 と RFC HTTP token ASCII grammar、
   value 長 0–16384 と HTAB または ASCII `0x20..0x7e` のみを検証する。
   name、value、予約名、過去の case-insensitive duplicate の順。
   予約名は `authorization`、`host`、`content-length`、`transfer-encoding`、
   `connection`、`trailer`、`te`、`upgrade`、`proxy-authorization`、
   `proxy-authenticate`、`expect`、`x-amz-date`、`x-amz-content-sha256`、
   `x-amz-security-token`。重複名は fold せず拒否。他の `date`、`range`、
   `content-type`、`content-md5`、`x-amz-*` を含む header は受け入れて署名する。
7. **V7 時刻:** `now_ns >= 0`。既存 UTC Unix nanosecond 表現を使い、小数秒を切り捨てる。
   すべての非負 i64 を受け入れ、現在時刻に対する freshness は判定しない。

S3 操作固有の header escaping は呼び出し側が必要に応じて済ませて渡す。signer は W3 の
空白正規化のみ行う。query/path は package が encode し、binary payload は変換しない。
検証後 HTTP constructor/setter に渡す text は NUL/CR/LF のない ASCII。secret/payload は
既存 length-delimited crypto/body API のみを通る。

## 厳密な署名と wire

1. **W1 target:** `uri = encoding.percent_encode_path(path)`。query name/value は
   `encoding.percent_encode` で encode 後、encoded name、encoded value の順に ASCII
   byte 昇順 sort し、`name=value` を `&` で結合。同一 pair も件数を保持する。
   URL は `origin + uri`、query 非空時だけ `?` と query を付加する。HTTP target は
   同じ URI/query、auto Host は明示 port を含む origin の authority substring と厳密一致。
2. **W2 body/time:** payload hash は空を含む全 body bytes の SHA-256 の小文字 hex。
   常に signed payload、`UNSIGNED-PAYLOAD`/chunk signing はない。
   timestamp は `basic_iso(now_ns)`、date はその先頭 8 ASCII bytes。
   scope は `date/region/s3/aws4_request`。
3. **W3 header:** user name を小文字化。value の前後 SP/HTAB を除き、内部の非空
   SP/HTAB 連続区間を一つの SP にする。他の byte/大小文字/句読点は保持し、wire value
   にも同じ正規化を使う。`host`、`x-amz-content-sha256`、`x-amz-date` と、Some 時だけ
   `x-amz-security-token` を追加し、全体を小文字 name 順に sort。
   canonical header は末尾を含む `name:value\n` rows。SignedHeaders は同じ name を
   `;` 結合する。user header はすべて署名し、Authorization と auto Content-Length は除く。
4. **W4 署名:** method、URI、query、canonical headers、SignedHeaders、payload hash を
   一つの LF 区切りで連結する。canonical headers 自体の末尾 LF により SignedHeaders の
   前は空行となり、最終 hash の後は LF なし。StringToSign は `AWS4-HMAC-SHA256`、
   timestamp、scope、canonical bytes の SHA-256 小文字 hex を LF 区切り、末尾 LF なし。
   raw 32-byte HMAC-SHA256 key を順に導出する。初回 key は `AWS4` + secret bytes、
   message は date。以降 message は region、`s3`、`aws4_request`。最後の key で
   StringToSign を HMAC し小文字 hex にする。中間 key は raw bytes で hex ではない。
5. **W5 request:** `http.request(method, url)` を構築し、Host を除く W3 の sort 済み
   rows、最後に Authorization を加え、空を含め body setter で一度 copy。
   Authorization は厳密に
   `AWS4-HMAC-SHA256 Credential=<access>/<scope>,SignedHeaders=<names>,Signature=<hex>`
   （comma 後 space なし）。HTTP は Host と Content-Length を追加し、明示空 body は `0`。
   wire 位置と CRLF framing は HTTP が決める。package は timeout/receive cap を上書きしない。

結果の body/signed header を後から変更すると署名対象が変わり、server が拒否し得る。
timeout/receive cap setter は署名 bytes を変えない。`http_request` を別 owner で包んだり
freeze したりしない。whole-body HTTP は 4xx/5xx を `Ok(http_response)` として返し、
呼び出し側が status と XML/body を既存 API で読む。stream error と client 借用 lifetime
も既存 HTTP 契約に従う。

## 公開使用例

以下は宣言と positional call であり、named argument ではない。

```align
import pkg.s3
import std.http

fn send(borrow client: http_client, credentials: pkg.s3.Credentials,
  endpoint: pkg.s3.Endpoint, headers: slice<pkg.s3.Field>, now_ns: i64,
) -> Result<http_response, Error> {
  request := pkg.s3.request(credentials, endpoint, "GET", "/bucket/key",
    headers[0..0], headers, "".bytes(), now_ns)?
  return client.request(request)
}
```

例の query slice は長さ zero で、query entry を借用しない。通常は別々の slice を渡せる。
要素型の共有は header/query value の関係を作らない。

## 実装 closure matrix と受入 owner

実際の imported package source を使う `crates/align_driver/tests/pkg_s3.rs` を driver
owner とする。名前は実装 checklist であり、一つの parameterized owner が複数 cell を閉じてよい。

| ID / owner | 義務と適用経路 |
|---|---|
| V1 `input_validation` | V1–V7 境界/次 byte・count、zero/empty/None/Some、禁止 authority/method/header byte class、全予約名と duplicate case、multi-invalid 順序。拒否時 header abort/network なし。UTF-8/NUL path/query escape、NUL secret/body の bytes 一致。 |
| W1 `signature_wire_vectors` | AWS 公開 GET range、PUT、lifecycle、list query vectors と独立 canonical bytes/hash/signature、捕捉した完全 target/header/body。nondefault/明示 default/先頭 zero port、host case、addressing 2 種、slash/dot/percent/UTF-8/NUL、並べ替え/同一/空 query pair、空白正規化、temporary token。semantic→wire と captured bytes→canonical signature の両方向を独立検証。 |
| C1 `ownership_and_consumers` | Copy field/credential/endpoint と借用 root。request の Result/Option/helper move、replacement/return、early Err/`?`/match/if/loop join/Drop は既存 HTTP suite を再利用。入力 arena を越える prepared request、準備後の source body 変更、一時 credential、whole/stream での一度だけの消費を追加。live stream が client を借りたまま第二 request が pool を使える。 |
| I1 `imports_effects_cache` | whole/per-unit × Dev/Release の同じ wire oracle、package resolution/vendoring/installed inventory、cold/warm cache、署名を変える private helper edit と厳密復元、record interface/borrow roots、parallel closure での Impure 拒否。新 native/IR tag なし。 |
| C2 `operation_round_trip` | local S3 peer が署名を検証して PUT/GET/HEAD/DELETE/list query を受け付ける。token、binary/empty body、shared pool、raw 403/500、transport failure、mid-stream Drop。cloud account 不要。共通 wire を証明し、各 compatible provider の認証取得済みを主張しない。 |
| H1 `align_runtime::http_explicit_body_framing` / driver `explicit_body_wire` | unset/明示 empty/nonempty と両方向 replacement、owner/view/get/post/batch。長さ計算と送信が同じ presence 条件。whole/stream・plaintext/TLS は同じ serializer、CL 重複なし。caller Host/CL 拒否を保持。peer は CL のない empty PUT を拒否し `0` を受け入れる。body hash に framing bytes を含めない。 |

不変の malformed HIR/MIR、generic、cleanup、interface、HTTP provenance は既存 owner で閉じる。
IR shape・ownership strategy・FFI signature・process-global state・callback・allocator path の
変更はない。probe で compiler defect が出たら、実装拡大前にその invariant を台帳に記録する。
performance/厳密 allocation count の約束はないので benchmark gate は設けない。

明示的な有効期間を持つpresigningの独立レビュー済み設計は
[s3-presign.md](s3-presign.md)で承認され、次は実装。
stream upload/chunk signing、multipart orchestration、typed XML listing/error、
pagination、credential refresh、SigV4a、S3 以外の service、provider 固有認証は将来機能。
通常 query/header 構築はこれらの上位 workflow を保証しない。
