# pkg — s3

> English is authoritative. Japanese mirror: `ja/s3.md`.
> Status: design candidate, 2026-09-09.

## Capability boundary

The first capability prepares an S3 SigV4 Authorization-header request from explicit
credentials, endpoint, time and request data. The returned `http_request` is directly
useful with the caller's existing `http_client.request` or `request_stream`. GET,
HEAD, PUT, DELETE, bucket queries and provider-specific headers use this same path.
This is request signing and construction, not an AWS operation/schema SDK.

The package owns canonicalization; `std.crypto` owns cryptography; `std.http` owns
transport, TLS, pooling, framing, timeouts and response ownership. Callers choose
virtual-hosted or path-style addressing by supplying the actual origin and absolute
unencoded path. For example, origin `https://bucket.s3.us-east-1.amazonaws.com` with
path `/key`, or origin `https://s3.us-east-1.amazonaws.com` with path `/bucket/key`.
There is no bucket-name inference, endpoint discovery, credentials file/environment
lookup, clock read, credential refresh, redirect following or package retry.

One ordinary vendorable subtree `apps/s3/pkg/s3.align` supplies `pkg.s3` and the
complete signer. Do not split canonicalization, signing and HTTP construction into
dormant producer PRs. The implementation may exceed 1,000 handwritten lines with
its wire and negative owners: testing the same signature-to-wire invariant once is
less risky than exposing intermediate strings through separate public seams.

The source probe also found one transport prerequisite inside this capability:
HTTP currently omits Content-Length when body length is zero, even after an
explicit `.body(empty)` or `post(url, empty)`. S3 requires it for PUT. Preserve
explicit body presence in the existing HTTP request owner/view and emit `0` for
an explicitly supplied empty body. This general HTTP rule ships with the signer;
it is not a special case keyed on S3, host, method or signature headers.

No persisted package format, reflection table, runtime secret registry or signing-key
cache is introduced. Ordinary package source/interface/dependency implementation
hashes determine whole-program/per-unit artifacts and cache invalidation. Public
record identities are nominal. Import capability collection follows the existing
module-wide rule and retains this module's HTTP, time, encoding and libcrypto rows.

no zeroization. There is no logging or diagnostic containing credentials/signatures.

## Deterministic validation

All V1–V7 validation completes before package allocation, hash/HMAC, request
construction or header setters. Invalid input cannot trigger HTTP's header abort.
Every rejected combination returns the same `Error.Invalid`; the order additionally
fixes the no-work boundary. Bounds are package admission limits, not provider limits.
Lengths are bytes; exact bounds are inclusive. All additions/multiplications use
prechecked bounded values and cannot wrap.

1. **V1, aggregate bounds:** `query.len() <= 128`, `headers.len() <= 120`,
   `body.len() <= 1073741824`. Empty query/header/body inputs are valid.
2. **V2, credentials:** access key length 1–256 and ASCII letters/digits/`-`/`_`;
   secret key length 1–4096, arbitrary bytes including NUL. Session token is
   `None`, or `Some` of 1–16384 bytes, each ASCII `0x21..0x7e`. Empty `Some`,
   whitespace, NUL and non-ASCII tokens are invalid. Check access, secret, token
   in that order. Credential provider authenticity is the server's decision.
3. **V3, endpoint:** origin length 1–1024; exact lowercase `http://` or `https://`
   followed by one nonempty authority, with no path, query, fragment, userinfo,
   percent escape, whitespace or non-ASCII. An unbracketed host contains only
   ASCII letters/digits/`.`/`-`/`_`, followed by optional `:port`. A bracketed
   host contains only hex digits/colon/dot, contains at least one colon, and is
   followed only by optional `:port`. Host spelling/case is preserved. Port is
   1–5 decimal digits with numeric value 1–65535; leading zeroes are accepted
   and preserved. This is lexical authority validation; DNS/IP existence and
   full address validity remain transport errors when sent. Region follows
   `[a-z0-9-]{1,64}`. Check origin then region.
4. **V4, method and path:** method is 1–32 uppercase ASCII letters. Path is
   1–8192 UTF-8 bytes starting with `/`. All later bytes, including NUL, `?`,
   `#`, `%`, repeated slashes and dot segments, are data for path encoding.
   It is never interpreted as an already-encoded URL or normalized. Check
   method before path. API-specific method/body/key restrictions are server-owned.
5. **V5, query:** in source order, name length 1–1024, then value length
   0–8192. Both are UTF-8 data; embedded NUL is valid and percent-encoded.
   Empty values and repeated names/pairs are retained. No pre-encoded escape
   interpretation. Reject any ASCII-case-insensitive name beginning `x-amz-`
   to exclude a second query authentication mode; ordinary S3 query names such
   as `list-type`, `prefix`, `continuation-token`, `versionId` and `uploads`
   remain data, not a package API registry.
6. **V6, headers:** in source order, name length 1–256 and RFC HTTP token ASCII
   grammar; value length 0–16384 and only HTAB or ASCII `0x20..0x7e`.
   Check name, value, reserved name, then prior case-insensitive duplicate.
   Reserved names are `authorization`, `host`, `content-length`,
   `transfer-encoding`, `connection`, `trailer`, `te`, `upgrade`,
   `proxy-authorization`, `proxy-authenticate`, `expect`, `x-amz-date`,
   `x-amz-content-sha256`, and `x-amz-security-token`. Duplicate names are
   rejected rather than folded. Other names, including `date`, `range`,
   `content-type`, `content-md5` and `x-amz-*`, are accepted and signed.
7. **V7, time:** `now_ns >= 0`. Epoch nanoseconds use the existing UTC time
   representation. Positive subsecond parts are discarded; every nonnegative
   i64 value is accepted. No current-time freshness check occurs locally.

Input headers may already contain protocol-specific escaping required by an S3
operation; the signer only performs W3 whitespace normalization. Query/path text
is encoded by the package; binary payload is not transcoded. After validation,
all text passed to HTTP construction/setters is ASCII without NUL/CR/LF. Secret
and payload bytes cross only existing length-delimited crypto/body APIs.

## Exact signature and wire contract

1. **W1, target:** `uri = encoding.percent_encode_path(path)`. Encode query
   names/values with `encoding.percent_encode`, sort by encoded name then
   encoded value in ascending ASCII byte order, and join `name=value` pairs
   with `&`. Equal pairs retain multiplicity and are byte-indistinguishable.
   `url = origin + uri`, followed by `?` and that query only when nonempty.
   The HTTP request target is exactly the same URI/query, and its auto Host
   value is the exact authority substring of origin, including explicit port.
2. **W2, payload and time:** payload hash is lowercase hexadecimal SHA-256 of
   all body bytes, including the empty body. Always use signed payload;
   no `UNSIGNED-PAYLOAD` or chunk-signing mode. Timestamp is `basic_iso(now_ns)`
   and date is its first eight ASCII bytes. Scope is `date/region/s3/aws4_request`.
3. **W3, headers:** lowercase each admitted user name. Trim leading/trailing
   SP/HTAB and replace each interior nonempty SP/HTAB run by one SP. Preserve
   other bytes, case and punctuation. Normalize the wire value identically.
   Add `host`, `x-amz-content-sha256`, `x-amz-date`, plus
   `x-amz-security-token` exactly when `Some`. Sort this complete set by
   lowercase name. Canonical headers are `name:value\n` rows, including a
   newline after the last row. SignedHeaders joins the same names with `;`.
   Every admitted user header is signed. Neither Authorization nor auto
   Content-Length participates in that set.
4. **W4, signing:** canonical bytes concatenate method, URI, query, canonical
   headers, SignedHeaders and payload hash with one LF between fields. Since
   canonical headers already end in LF, one blank line separates them from
   SignedHeaders. No LF follows the final payload hash. StringToSign is
   `AWS4-HMAC-SHA256`, timestamp, scope and lowercase hex SHA-256 of canonical
   bytes, separated by LF with no trailing LF. Derive raw 32-byte HMAC-SHA256
   keys successively using key `AWS4` plus secret bytes and message date,
   then messages region, `s3`, `aws4_request`; use the final key to HMAC
   StringToSign and lowercase-hex the result. Intermediate keys are raw bytes,
   never hex input to the next HMAC.
5. **W5, request:** construct `http.request(method, url)`, add the sorted W3
   rows except Host, then Authorization last, and copy body exactly once via
   the existing body setter (including empty input). Authorization is exactly
   `AWS4-HMAC-SHA256 Credential=<access>/<scope>,SignedHeaders=<names>,Signature=<hex>`
   with no spaces after commas. HTTP adds Host and Content-Length, including
   `0` for the explicitly supplied empty body. HTTP determines their wire positions
   and CRLF framing. No package timeout or response cap override is installed.

Caller mutation of body or signed headers after `request` changes the signed
message and may cause server rejection. Configuration setters for timeout/receive
cap do not change signed bytes. The package does not wrap or freeze `http_request`;
the existing ownership model makes request construction and subsequent mutation
visible. Whole-body HTTP returns 4xx/5xx as `Ok(http_response)`; callers inspect
status and XML/body through the existing HTTP/XML APIs. Streaming response errors
and dependent client lifetime retain the HTTP contract.

## Public use

These are declarations, not named call arguments:

```align
import pkg.s3
import std.http

fn send(borrow client: http_client, credentials: pkg.s3.Credentials,
  endpoint: pkg.s3.Endpoint, headers: slice<pkg.s3.Field>, now_ns: i64,
) -> Result<http_response, Error> {
  request := pkg.s3.request(credentials, endpoint, "GET", "/bucket/key",
    headers[0..0], headers, "".bytes(), now_ns)?
  return client.request(request)
}
```

The zero-length query slice in the example borrows no query entries. A normal
caller may supply independent slices; sharing the element type adds no relation
between header and query values.

Existing compiler malformed-HIR/MIR, generic monomorphization, recursive cleanup,
interface serialization and HTTP runtime provenance owners close unchanged
machinery. No IR shape, ownership strategy, FFI signature, process-global state,
callback or allocator path changes. If a package probe exposes a compiler defect,
record that invariant here before expanding implementation scope. No performance
or exact allocation-count promise is made, so no benchmark gate is added.

Presigning, streaming upload/chunk signing, multipart orchestration, typed XML
listing/error records, pagination, credential refresh, SigV4a, non-S3 service
signing and provider-specific authentication remain future capabilities. Ordinary
query/header request construction does not promise those higher-level workflows.
