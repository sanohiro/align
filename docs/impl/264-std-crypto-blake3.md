# BLAKE3 on the native digest path

The C implementation maintained by the BLAKE3 project is now packaged as a system library on macOS and Debian. This satisfies the engine requirement recorded in std.crypto's design. Older Ubuntu/Debian releases can install the same upstream implementation from a verified release.

| Contract | Ownership, implementation and acceptance |
|---|---|
| Public form | With `import std.crypto`, `crypto.blake3(data:bytes) -> array<u8>` produces the 32-byte standard unkeyed BLAKE3 digest. Use the existing digest byte-view input checker, including UTF-8 string auto-view and embedded NUL; any existing rejected byte-argument shape stays rejected. Exactly one expression, evaluated once before the call, no options and no defaults. Same Impure effect as the existing one-shot digest family. Empty bytes hash to the published empty vector. Digest bytes have no text encoding. |
| Storage, errors | Input is borrowed for the call. The caller owns exactly one independent 32-byte allocation, including inside arenas. Mutating/dropping input cannot affect the digest. No recoverable engine status; the official fixed-width API is infallible, allocation exhaustion follows ordinary terminal policy. Typing, temporary cleanup, early return, assignment/replacement, dropped result, branch joins, generic/import forwarding and cached units reuse CryptoHash + ordinary owned-array rules. No key, XOF, streaming state or new resource handle is advertised. |
| Native interface | `align_rt_crypto_blake3(ptr data, i64 length) -> AlignStr` has the same ABI shape and pointer effects as existing one-shot 32-byte crypto digests (an owned {ptr,len} with len=32). Valid positive input must be readable; null/zero and the existing digest boundary treatment for invalid/null lengths use the same checked bytes view, with no raw null Rust slice. Put the actual exported align_rt_crypto_blake3 wrapper in its own C archive member, with no references to it from the shared Rust runtime object. Use the target compiler and installed `blake3.h`; allocate `blake3_hasher` using its actual C type, call init/update/finalize, and use `BLAKE3_OUT_LEN` with a compile-time assertion that it is 32. Write directly into the exact owned output with disjoint live input. The stack state dies at call end. No recreated C layout, custom crypto, BLAKE2 substitution, dynamic symbol guessing or runtime network retrieval. |
| Dependencies and distribution | The compiler build compiles the adapter using the target C compiler and target provider header. Classify BLAKE3 independently from libcrypto using the existing union across all lowered functions, including an uncalled non-generic helper. Keep compile-time link selection distinct from the runtime image's dependencies after dead stripping. For a selected BLAKE3 capability link the companion `libblake3.a` by exact path immediately after libalign_runtime.a when present in the trusted runtime's own directory. Otherwise source-built toolchains link the platform `-lblake3`. Without the capability add neither. Preserve an explicit extern link(\"blake3\") request independently of automatic companion substitution. Exercise extern-only, builtin-only and both on cache hits; the compiler must be able to distinguish the origin through link replay. Pure SHA/TLS operations keep their current dependency sets. The exported wrapper alone calls the provider and align_rt_alloc; this way ELF archive extraction never introduces a provider reference when using other members. Building the runtime/tests from source requires the provider header and library. Every official prebuilt toolchain includes the PIC static upstream provider as a separate archive beside the runtime (macOS/Linux tar, installed Homebrew libexec and Noble amd64/arm64 .deb), plus upstream license, so applications compiled with it have no runtime BLAKE3 dylib dependency and apt install alignc remains sufficient. Extract and smoke-test the distributed artifact on a clean Noble host without libblake3-dev, on arm64 as well as amd64, and verify the Homebrew installation preserves the relative layout. Do not publish an additional Debian package or mix distro suites. Linux CI/release hosts lacking distro packages provision official C release 1.8.7 using pinned tarball SHA-256 c6782a28842b1c0478524ac06a4f2ede784038ee298d6e2162c0b089c4306a3c and CMake with TBB disabled and BUILD_SHARED_LIBS=ON for ordinary source/CI links. Build the release companion separately with BUILD_SHARED_LIBS=OFF and position-independent code. Install into an explicit prefix or disposable system image. System libblake3-dev and Homebrew blake3 remain supported. Document the same setup for end users without mixing unstable distro suites. Check required CI, nightly, release binaries/profiling, Homebrew dependencies, supported Linux package installation and local tests using the same provider. Preserve source/checksum and missing-engine usability of unrelated prebuilt programs. No silent configure-time download; installation is explicit. |
| Cache and owners | Extend the closed HIR/MIR digest discriminator and its stable print, runtime key/effect/ABI table, declaration golden, HIR ledger, runtime export verification and native link collector. A change of SHA256 to BLAKE3 must invalidate code and link identity. Extend the independent native signature audit to compile the exported C wrapper to target-matched LLVM IR and validate the exact return/arguments alongside the Rust inventory; keep strict symbol counts. Both runtime_src_digest implementations cover the adapter C file. Cargo reruns the C build on provider header/toolchain location and wrapper change. Whole-program, unit, watch and REPL builds always relink, observing current companion bytes on every build. A future executable cache must key its selected archive contents. The unit manifest uses version 2, encoding each link origin with one byte: 0 followed by a length-prefixed UTF-8 system name, or 1 alone for the compiler BLAKE3 provider. Reject unknown and truncated tags. The unit key format stays unchanged. Verify exact linker arguments for SHA-only/BLAKE3-only/both/unrelated/unused-helper programs in whole, per-unit and warm cache. Exercise GNU ld and ELF lld on Linux and Apple ld64 on macOS, verify actual built executables and their DT_NEEDED/LC_LOAD_DYLIB dependencies under dynamic and packaged-static providers. Ordinary executables and SHA-only programs must build and run with no provider present beside the prebuilt toolchain or in system search. Test official vectors for empty, "abc", binary contents, exact 64-byte block and 1024-byte chunk boundaries plus multi-chunk input. Use the upstream official independent known-answer corpus, not the linked library to produce expected answers. Exercise exact output size, independent storage and Drop via allocation probes. Existing SHA digests remain controls. No new performance promise. Sources draft, language digest, design-notes, open-questions, roadmap, std-design/crypto English/Japanese, ledgers 19/20, build and release instructions. |

## Implementation closure and owners

| Boundary | Production path and owner |
|---|---|
| Borrowing, moves, allocation and cleanup | Existing CryptoHash and DynArray(u8) rules cover branches, returns, early exits, reassignment and generic replay. `m11_crypto::blake3_official_vectors_and_owned_results` retains each result after its input dies. `blake3_allocates_one_owned_result_in_or_out_of_an_arena` counts the exact allocations, live bytes and frees. |
| Link origin and cache | MIR NativeLibrary distinguishes a system request and a provider. The unit manifest, whole/package build, REPL, watch and ThinLTO retain the discriminator to the final link. `capability_linking` checks both object formats. `unit_cache` checks explicit, implicit and combined origins on repeated builds, including an uncalled function. The manifest golden covers both tag directions and malformed inputs. |
| Native and packaged execution | `test-runtime-abi-exports.sh` audits the C adapter with target-matched clang. `test-blake3-package.sh` tests a relocated runtime, archive replacement on a warm build and the SHA-only control. The release workflow checks Homebrew installation and both extracted Debian package payloads. |
