# Fused group aggregation on SoA columns

The existing `group_by(.key).agg(...)` grammar and result extend to a bound
`soa<R>` with the same key and value field types as single-aggregate SoA.
One scan interns each string key or looks up each integer key once per row
and updates every requested aggregate. This capability uses column projection;
a later change to SoA's physical view representation can keep that projection
as its sole addressing rule. The native producer, its consuming backend and its
checked input and output types ship together. Their independent tests account
for most of the change near 1,000 lines. A producer-only PR would expose an
untested ownership transfer without a working language consumer.

| Surface or invariant | Contract, implementation and acceptance |
|---|---|
| Types and inputs | Bound local or parameter of exact `soa<R>`, one existing named `str` or signed `i64` key. One or more ordered aggregate specifiers `sum(.v)`, `min(.v)`, `max(.v)` on signed `i64` fields or `count()`. Repeated fields and operations, and the i64 key as a value field are legal. No defaults, callbacks, user code or expressions inside specifiers. Reuse the existing sema syntax, arity, field checking and error precedence. Pure. Result is `(array<Key>, array<i64> × K)` with one element per distinct key in every column. String groups retain first-occurrence order. Integer groups are unordered, like the single-aggregate SoA operation. All columns align to the emitted key order. Sum wraps, count adds one and extrema seed from the first row. Empty input yields K+1 empty arrays. Existing AoS/encoded input admission for fused grouping is unchanged. |
| Ownership and control | Allocate one independent heap key column and one independent heap i64 column per aggregate, including inside arenas. Numeric keys/values retain no input. String key elements retain the exact source key field's payload lifetimes and validated bytes, separately from the heap headers. A numeric member can escape a shorter-lived key input subject to ordinary projection/move rules. No component may claim exclusive access through a shared key. Return, selected field/index, project/drop/replacement, moved tuple/nulling, helpers and generic/imported calls, if/match/loop joins and early exits reuse existing owned-tuple machinery. HIR generation and return roots must admit SoaI64/SoaStr and reject mismatched source tags. Verify whole/per-unit and warm cache object identity against layout, key kind, field selection and aggregate order. |
| MIR | `GroupAggMultiCols { base: Slot, struct_id, key_field, aggs }` yields exactly `Ty::Tuple` with K+1 owned dynamic arrays. The key scalar comes from the row definition, followed by K signed i64 columns. Authenticate the exact local type Soa(struct_id), row/field ids, all operations, nonempty K and extent fitting u32 K+1 in checked HIR and MIR, even when unused. Require founded readable SoA and selected fields at the use; empty selection paths classify the owning tuple and column headers Owned, numeric elements independent, selected str element Shared bounded by the actual key field. Validate all paths, foreign result tuple/slot/op/field, independent modules and unused producers. No allocation pointer, status, uninitialized slot or partial header construction exists in MIR. The owned tuple uses the ordinary Move/Drop/replace/return path. |
| Layout, control and allocation | Load the source slot once into one LLVM SSA descriptor within the lowering of this sole MIR operation; all length and key/value column addresses derive from that SSA and the canonical SoA addressing. No source expression or user code can be evaluated between those accesses. Source-slot rebind before the operation picks the new descriptor, rebind after it cannot affect which columns were read. Allocate a fixed K-element spec table and K+1 output headers in the function entry block. Never expose their addresses as language/MIR values. Codegen emits a scalar return guard before loading the table or constructing the tuple: native -1 routes to terminal runtime abort, success 0..=n. Explicit MIR semantics include this failure arm, as for other indivisible native producers. Verify emitted guard and one fused call per invocation, including loops and early return. |
| Native | Retain A40: i64 align_rt_group_multi_cols(ptr keys, ptr specs, i64 n, ptr headers, i64 k, i64 key_kind). Spec is C-layout {const i64* values, i64 op}, 16 bytes; headers is an exclusive aligned writable array of K+1 AlignStr (16 bytes each), disjoint from inputs, specs and represented key bytes. This table is always nonnull, even for empty input. Its first result describes a contiguous array of i64 keys (tag 0) or borrowed str headers (tag 1), followed by K contiguous arrays of i64; all lengths equal returned group count. No output buffer addresses from the caller. Check kind/n/k, spec/output table sizes and alignment, required input ranges, all ops and column pointers before row lookup. Count uses null input. For n=0 valid column pointers may be null and all K+1 published headers are null/0. Before reading key bytes, check the length is nonnegative and addressable and that a nonempty payload is nonnull. Compare all bytes including NUL. Check group × K cells and their byte extent before growth. Any invalid input returns -1 leaving all header cells unchanged. No per-call ambient randomness. |
| Native ownership | Stage representatives and all accumulators in scan order. After validation and checked representability, allocate exactly one independent align_rt_alloc block per nonempty result column, sized by actual group count, not row count. Materialize the key headers or i64 keys and each numeric column before exposing success. No recoverable action follows first allocation; OOM is terminal, with no partially returned value. Free only staging; Align's tuple Drop frees each published payload exactly once. Input and arena text are always borrowed. Native success/error/cache controls and alias tests cover group/native output headers, not preallocated payload pointers. Record ordinary alloc/free and requested live bytes for large N small group count. No timing threshold. ABI effects IndirectStorage/Unstated and escapes [0], ordinal 1/3 captures(none); no writeonly, release or fresh scalar return. |
| Validation | An injected PtrStore, alias, free or second writer cannot address the hidden output table or payload pointers prior to publication in MIR. A compiler transformation cannot schedule any output allocation after the call. Forged whole/partition negatives exercise malformed source, key, op, type or tuple shape. Check removal of any obsolete graph-wide publication scan. Keep the existing AoS path and its ABI untouched. Benchmark prepared source against repeated real operations, accounting for per-call output allocation on both paths, comparing every aggregate by key. |
| Source initialization and lifetimes | Every reachable path to the operation supplies a complete current source, including a dominating definition of the stored descriptor. Out parameters have no incoming value. Test later-only stores, one-sided joins and validated rebinds. Two independently validated text fields prove invalidation follows only the selected key; numeric columns retain neither field. |
| Loop scratch | Reuse entry scratch by overwriting header bits after successful calls, including empty results. Copy values into each tuple; scratch never owns a payload. Verify two live results, failed calls leaving scratch intact, and exact allocation/free parity. |
| Explicit SSA inputs | At each executable statement in a function containing fused grouping, check the immediate operand uses against unique actual MIR definition locations. A value requires dominance of the use block and strictly earlier definition in its own block. Record call/parse auxiliary cleanup SSA at their defining statement. Constants and legitimate incoming arguments have no SSA dependency, but they do not initialize out slots. Walk nested call, closure, template and borrowed-place descriptors, plus statement and terminator operands including guards and cleanup flags. Derive or exhaustively match operands without a default-ready variant. An affine identity or a branch must not erase this check. Cover the Select future-definition reproducer, earlier/later same-block and sibling diamonds, tuple pack/projection, forward aliases, calls, condition/mixed-typed operands, cycles and loop-carried control. |
| Slot reads | Retain a CFG must-initialization proof at the actual group read, across branches, loops and kills. Authenticate transitive loads through direct or aggregate SoA forwarding, including result/option/tuple/record projections. Only actual incoming values, whole or appropriate projected stores, and established native out producers initialize a descriptor. A compiler temporary's eventual Store does not establish prior readability. Keep selected published outputs private to the atomic operation. |
| Owner field selection | Store typed field paths of ordinary owners as well as UTF-8 validations at transpose and at dynamic AoS materialization. Preserve exact known projected dependencies when materializing and reading collections, keeping direct unknown/caller facts conservative. Only the chosen string field passes to tuple path 0. Include fixed and dynamic records with two distinct owned strings/views, changing selected/unselected owner while output then remains live. Existing stable-header and borrow/move/projection suites verify shared paths. |
| Boundary | Keep this validation change with its first consumer inside the one capability PR. Compile-time field coverage and the projection and CFG owners exercise the expanded boundary. An executable generic cache consumer, native isolated audit and scoped HIR/MIR negatives continue to apply. A larger diff is necessary to prove every indirect expression kind, instead of treating a short whitelist as evidence that all derived values are well-founded. |

On Linux x86_64, a release runtime grouped 250,000 prepared rows with 1,024
distinct four-byte keys. All four results (sum, min, max, count) were checked
by key against independent calls. The median of nine alternating trials after
warmup was 2.412 ms fused and 8.450 ms separate. Timings include allocation of
all returned columns and exclude input preparation, verification and Drop.
