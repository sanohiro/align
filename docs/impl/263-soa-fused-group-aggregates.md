# Fused group aggregation on SoA columns

The existing `group_by(.key).agg(...)` grammar and result extend to a bound
`soa<R>` with the same key and value field types as single-aggregate SoA.
One scan interns each string key or looks up each integer key once per row
and updates every requested aggregate. This capability uses column projection;
a later change to SoA's physical view representation can keep that projection
as its sole addressing rule.

| Surface or invariant | Contract, implementation and acceptance |
|---|---|
| Types and inputs | Bound local or parameter of exact `soa<R>`, one existing named `str` or signed `i64` key. One or more ordered aggregate specifiers `sum(.v)`, `min(.v)`, `max(.v)` on signed `i64` fields or `count()`. Repeated fields and operations, and the i64 key as a value field are legal. No defaults, callbacks, user code or expressions inside specifiers. Reuse the existing sema syntax, arity, field checking and error precedence. Pure. Result is `(array<Key>, array<i64> × K)` with one element per distinct key in every column. String groups retain first-occurrence order. Integer groups are unordered, like the single-aggregate SoA operation. All columns align to the emitted key order. Sum wraps, count adds one and extrema seed from the first row. Empty input yields K+1 empty arrays. Existing AoS/encoded input admission for fused grouping is unchanged. |
| Layout and representation | Read the existing SoA key/value columns with the canonical column addressing over the certified allocation extent, for any legal row layout (padding, early small fields, repeated aggregates, numeric or str key). Every source column has the same visible length. Project only fields used; count reads no value bytes. No transpose or repeated per-aggregate group calls. Do not accept independently assembled slices with unproven matching extents. Load the SoA descriptor once into one captured SSA operand. Derive the length that sizes every output, every key/value projection, and the native call from this exact operand. MIR carries the captured value, exact nominal struct, source key kind, field ids, ordered ops and output operands. A later slot rebind cannot change the operation's source. Require distinct allocations and a unique writer, corresponding output index and exact success count for publication. |
| Ownership and control | Allocate one independent heap key column and one independent heap i64 column per aggregate, including inside arenas. Numeric keys/values retain no input. String key elements retain the exact source key field's payload lifetimes and validated bytes, separately from the heap headers. A numeric member can escape a shorter-lived key input subject to ordinary projection/move rules. No component may claim exclusive access through a shared key. Return, selected field/index, project/drop/replacement, moved tuple/nulling, helpers and generic/imported calls, if/match/loop joins and early exits reuse existing owned-tuple machinery. HIR generation and return roots must admit SoaI64/SoaStr and reject mismatched source tags. Verify whole/per-unit and warm cache object identity against layout, key kind, field selection and aggregate order. |
| Native interface | New internal `i64 align_rt_group_multi_cols(ptr keys, ptr specs, i64 n, ptr out_keys, i64 k, i64 key_kind)` (A40). kind 0=i64, 1=AlignStr. Each C-layout spec is `{ptr values, i64 op, ptr out}` (pointer/i64/pointer, 24 bytes on supported 64-bit ABIs). 0=sum, 1=min, 2=max, 3=count. Count has null values; every other op reads one contiguous i64 column of n. Keys read n typed elements, i64 or 16-byte str header. Each output is exclusive, aligned, capacity n, mutually disjoint and disjoint from live inputs/specs and every represented string payload. Input columns may alias each other; selected text may contain NUL and is compared byte-for-byte. No encoding or OS boundary. Keyed GroupMultiCols, IndirectStorage/Unstated. Input keys may supply returned text and carry no nocapture; spec pointer refers to read-only descriptors containing input and output pointers; it never escapes, and output-key pointer never escapes. Pointer ordinals 1 and 3 get captures(none); only ordinal 0 may escape. No writeonly, noalias, return-fresh, release, or argmem promises. Use no read attribute on the descriptor parameter so indirect writes remain conservatively modelled. |
| Failure and bounds | Validate kind, n, k>0, k×24, n×8 and n×key width for signed addressability before reading the spec table. Validate the table pointer and its native alignment first, then every op and nonempty column's required pointer/alignment before reading any row. Native callers guarantee readable descriptor/key/value ranges of the stated lengths, exclusive writable output capacity n and disjointness as above; sizes and arithmetic do not prove foreign pointer liveness. During the scan validate every str header length is nonnegative and addressable and the data pointer is nonnull for a nonempty string. A null+zero str denotes the empty key. Represented text may contain embedded NUL. For n=0, null column and output pointers are allowed and a valid spec table still carries the K operations. Negative/malformed counts and foreign tags give -1 without writes. Native callers guarantee readable/writable disjoint ranges for positive extents and nonempty text views. Stage all keys and accumulators before publishing successful group count. Check group×K and accumulator byte extent before growth; an unrepresentable extent returns -1. Actual allocation failure remains terminal. Check K fits the backend's table index/count domain and native i64 without truncation. Place fixed compile-time descriptor storage once in function entry so execution inside a loop never consumes unbounded stack space. MIR routes native failure to a terminal runtime panic before constructing owned result headers; successful count is 0..=n. Tests cover zero, singleton, duplicates, sparse/sign-extreme integers, equal strings from distinct backing incl NUL, overflow, wide padded structs, all op permutations, bad specs and sentinel outputs. |
| Producer and ABI | Use one fused MIR writer, authenticating even a discarded result. Check selected key type, all operands/slots, initialized source slot, count arity and op/field domain, exact owning output allocation type/extent, distinct output buffers, matching writer and published extent for all outputs, checked HIR, whole and partition validator. Group tuple key and numeric results receive only the appropriate access provenance. Prefer shared allocation/tuple publication and fold implementation with AoS when existing invariants agree. Keep existing AoS runtime ABI and cache records compatible. Print source/call/input identities deterministically, update registry, declarations/exports and HIR ledger. |
| Acceptance | `align_driver/tests/soa.rs` exercises both SoA key kinds, AoS control, multiple K and row layouts and returns/deep Drop; MIR/HIR owner mutates sources, fields, spec counts, buffers and count producers, including same-slot rebind/different descriptor issuance, second writer for a returned allocation, swapped same-typed output columns, mismatched visible extent and unused malformed calls in whole and partition validation. Native tests assert C layout/bounds and direct output. One local apples-to-apples SoA measurement compares fused to repeated independent calls on the same prepared source; compare results by key before computing the checksum, verify one MIR/native call and at most one row-key lookup per row regardless of K. No wall-clock ratio is promised. Normative sources draft §9, language-spec, design-notes, open-questions, roadmap, core-design/soa-groupby and ja, HIR19/runtime20. No persisted format or public CLI option. |

A local Linux x86_64 release-runtime measurement grouped 250,000 prepared rows
into 1,024 distinct four-byte string keys. It compared sum, min, max and count
against four separate calls over the same columns and checked every output by
key. Across nine alternating timed trials after warmup, median time was 2.55 ms
fused and 8.52 ms separate. All input and output arrays were allocated outside
the timed interval.
