# std.time の通信形式とパスエンコード

英語の [time.md](../time.md) が正本です。2026-09-08 に再開したクラウド系の前提機能として、
日時の形式群とスラッシュを保存するエンコードを一つの実装 PR で提供します。
次の利用者は `pkg.s3`／SigV4 です。この機能自身は通信を行いません。

## 公開契約

既存の `now`、`instant`、`sleep` は変更しません。時刻は符号付き `i64` の Unix epoch
ナノ秒、UTC、先発グレゴリオ暦です。ロケール、タイムゾーン DB、strftime、新しい時刻型、
うるう秒用の時系列は導入しません。

| 関数 | 正規出力 | 分解能（ns） |
|---|---|---:|
| `time.rfc3339(ns: i64) -> Result<string, Error>` | `YYYY-MM-DDTHH:MM:SS[.fraction]Z`。ゼロの小数部は省略、それ以外は末尾ゼロなしの 1–9 桁 | 1 |
| `time.rfc3339_ms(ns: i64) -> Result<string, Error>` | `YYYY-MM-DDTHH:MM:SS.sssZ`。小数部は常に 3 桁 | 1000000 |
| `time.rfc1123(ns: i64) -> Result<string, Error>` | `Wdy, DD Mon YYYY HH:MM:SS GMT`。固定の英語名 | 1000000000 |
| `time.basic_iso(ns: i64) -> Result<string, Error>` | `YYYYMMDDTHHMMSSZ` | 1000000000 |
| `time.basic_date(ns: i64) -> Result<string, Error>` | `YYYYMMDD`。UTC の午前 0 時 | 86400000000000 |

各関数は負の時刻も含めて数学的な床関数で分解能へ切り捨てます。その値が `i64` の範囲外なら、
割り当て前に `Error.Invalid` を返します。成功時は所有する Move `string` を返します。
ナノ秒精度の関数はすべての `i64` を受理します。成功した出力は対応する解析関数で切り捨て後の
時刻へ戻せます。クランプやラップは行いません。割り当て失敗は既存の文字列の hard-OOM 規則です。

対応する解析関数は `time.parse_NAME(input: str) -> Result<i64, Error>` です。
NAME は上記の `rfc3339`、`rfc3339_ms`、`rfc1123`、`basic_iso`、`basic_date` のいずれかです。
デフォルト引数や省略可能な引数はありません。`string` は通常の呼出し中だけの `str` 借用へ
変換します。解析は入力を保持せず、割り当てず、Copy 整数を返します。追加するすべての操作は
既存のエンコーダと同じ決定的な Pure 変換です。

解析はトリミングせず入力全体を消費します。NUL、非 ASCII、不正な暦日、時 > 23、分または秒 > 59、
余分なバイト、正規化後の範囲外ナノ秒を `Error.Invalid` とします。うるう秒は翌日へ丸めず拒否します。
年は厳密に 4 桁、他の数値欄も表示した固定幅です。RFC1123 は表示した IMF-fixdate のみを受理し、
英語名と GMT の大文字小文字を区別し、曜日と暦日の一致を検査します。古い HTTP-date 文法は対象外です。
基本形式の解析は各フォーマッタの厳密な文法のみを受理します。

RFC3339 系のみ、小文字の t/z、`+HH:MM`／`-HH:MM` も受理します。オフセットの時は 00–23、
分は 00–59、未知のローカルオフセットを表す `-00:00` は拒否します。オフセットを減算してから
表現範囲を検査します。`parse_rfc3339` の小数部は省略または 1–9 桁、`parse_rfc3339_ms` は
厳密に 3 桁です。他の区切りは固定です。不正入力はすべて同じ `Invalid` であり、メッセージの
優先順位は公開しません。

`encoding.percent_encode_path(data: bytes) -> string` は既存の `percent_encode` と同じ
bytes／str／呼出し中だけ借用する string を受け取ります。ASCII `A-Z a-z 0-9 - . _ ~ /` を保存し、
他の全バイトを大文字 `%XX` にします。既存エスケープのデコード、連続スラッシュやドット区間の
正規化はしません。出力は独立所有で、割り当て規則も既存エンコーダと同じです。encode-only であり、
共通の `percent_decode` で元のバイトへ戻せます。URI／クエリ構造、オブジェクトキー境界、SigV4 の
正規化は利用側が所有します。

## コンパイラとネイティブ境界

Sema が正確な引数数、型、種類、結果を検証します。HIR は閉じた 5 種類の `TimeFormatKind` と
`TimeFormat { kind, ns }`／`TimeParse { kind, input }` を使用し、MIR は種類を保存して既存の
status→Result と所有文字列の cleanup を使用します。LLVM は検証済み MIR を下げるだけです。
`EncodingKind::PercentPath` を decoder に入れた不正 HIR は HTML と同様に拒否します。

| RuntimeKey | 厳密な ABI | 出力 |
|---|---|---|
| `TimeFormat` | `i32 align_rt_time_format(ptr out, i64 ns, i32 kind)` | `AlignStr { ptr, i64 len }` |
| `TimeParse` | `i32 align_rt_time_parse(ptr out, ptr input, i64 len, i32 kind)` | `i64` |
| `PercentEncodePath` | `{ptr, i64} align_rt_percent_encode_path(ptr input, i64 len)` | 既存の所有文字列 ABI |

種類タグは 0 RFC3339、1 RFC3339-ms、2 RFC1123、3 basic-ISO、4 basic-date です。
時刻関数は成功 0、失敗 EINVAL を返し、既存の errno→Error 変換を使います。他のタグは拒否します。
呼出し側は有効で適切に整列した書込可能出力領域を提供します。不正な NULL／整列／長さ／アドレス範囲の
メタデータは不正な領域を参照せず拒否します。有効な出力は失敗時にもゼロ初期化します。入力への Rust
参照を作る前に生アドレスで重複を検査し、重複時は有効な出力をゼロにして入力を読まず拒否します。
NULL 入力は長さゼロのときだけ許可しますが、空入力は時刻文法として不正です。有効な非空入力は
呼出し中読出し可能な初期化済みバイト領域です。解析はスライス作成前に最大 35 バイトを検査します。

保持ポインタ、コールバック、プロセス状態、リソースシェル、新しい所有権モードはありません。
整形は固定長のスタック領域へ書き、その後一つの所有文字列を割り当てます。暦変換と正規化は幅を
広げた整数演算で中間オーバーフローを防ぎます。ネイティブ依存は追加しません。

種類と子式を HIR と単相化で保存します。ジェネリック interface は HIR の種類番号ではなくソースを
保存するため、既存 schema は変更しません。キャッシュ再構成テストが種類と子式を含む MIR を検証します。
3 キーを ABI の台帳と fingerprint に含めます。通常／単位別コンパイルは通常のコンパイラ、
インターフェース、ランタイムのキャッシュ識別を使用します。別形式や別キャッシュ経路は設けません。

## 実装の完了範囲

英語版の実装マトリクスが具体的な所有テストを管理します。対象は以下の全軸です。

- 5×2 API の型・引数・不正 HIR、暦と精度、両端点、文法の各欄と正常対照。
- ネイティブ出力のゼロ化、NULL、整列、長さ、重複、不正種類と厳密な ABI。
- MIR の読出し権限、正確な入力／status／出力スロット型、種類、完全な式の検証後の所有権公開。
  不正な生成元、アクセス権、型、結果、出力スロットは拒否し、通常／単位別の正常例も所有する。
- 生成、束縛、unwrap、戻り値、既存コンテナ、move-in/out、移動元 null 化、Drop、置換。
- if、match、else、?、map_err、分岐／ループ合流、早期 return、終了する引数と一度だけの評価。
- 直呼出し、helper、import、ジェネリック再生、非捕獲の間接 wrapper、クロージャと Pure 判定。
- percent の全 256 バイト、空、借用／所有、既存エスケープ、スラッシュ、ドット区間、decoder 拒否。
- 通常／単位別一致、ジェネリック interface、cold／warm／変更／復元とキャッシュ無効化。

暦、Result、ABI、永続化、所有権の共通証明を分割しない一つの有用な前提機能です。手書き変更が
1,000 行を超えても、形式別や休眠した生成側／消費側へ分割すると証明が重複し、統合リスクが増えます。
性能の明示的な約束はないためベンチマークのゲートはありません。
直接の builtin 関数値、返却／捕獲クロージャの制限緩和、任意書式、ロケール／TZ、古い HTTP-date、
うるう秒、S3 通信、外部利用リポジトリの採用作業は対象外です。

レビュー前に各適用セルを実装と区別能力のあるテストへ対応させます。仕様、要約、設計理由、Settled、
roadmap、HIR／ABI 台帳とこのミラーを同期します。RFC3339／HTTP-date の完全対応は主張しません。
一次資料と正確な参照先は英語版の Sources and consistency 節にまとめます。

英語版の R1–R5、D1–D6、H1、P1、C1、A1–A2 が実装済みの正確なテスト名を示します。
HIR／ストレージの種類数は 327 です。不正なネイティブタグは R4 で検証し、Rust の閉じた列挙型へ
不正タグを作る未定義動作は行いません。D1 は未実装の旧版とネイティブ envelope の受理漏れを、
P1 は整数だけの解析結果の生成元検証漏れを検出し、作者側で修正しました。明記した対象外の行を除き、
各セルに実装とテストがあります。このために他のコンパイラ制限を緩めていません。
