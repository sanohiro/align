# Scalar operands in core.vec select

| Boundary | Contract and owner |
|---|---|
| Expression | `select(mask: maskN<M>, yes, no) -> vecN<T>`. At least one data operand has type `vecN<T>`. The other has type `vecN<T>` or `T`. The existing numeric element and lane-count domains apply. M and T have the same lane bit width. The mask supplies one choice per lane. Two scalar data operands are rejected even with an expected vector result. |
| Evaluation | Evaluate mask, yes and no eagerly, once each in source order. A non-fallthrough child skips the remaining operands and the blend. Replicate the scalar's exact bits into N lanes, including floating-point signed zero and NaN payloads. The operation is Pure and Copy with no allocation, runtime checks or cleanup. Child effects follow ordinary expression rules. |
| Inference | Pass contextual vector and scalar candidates to the existing numeric expression checker. A concrete expected vector permits either operand to be a vector literal. With no expected type the already-checked left vector can supply the right vector literal's type. A bare left array literal without vector context remains an array, even when the right operand is a vector. A leading numeric literal can unify with the element of a later vector. Typed scalars must match the element exactly. Nested calls obey the same rule. Mismatched mask dimensions, element types, scalar-only data and invalid arity are compile-time errors. |
| Compiler | Sema records each expression once in HIR Select. Both the HIR envelope and flow validators check the data relation, structural mask and vector result. MIR materializes one MakeVec at the scalar's evaluation position and then emits the existing vector Select. All emitted MakeVec producers authenticate the legal numeric width, lane count, element operands and their producers, including dead results. Masked MIR Select takes two complete vectors. Ordinary scalar-condition selects retain their existing relation. LLVM lowers the same MIR as an explicit vector blend. |
| Delivery | Compiler identity covers the change in source acceptance and MIR. The type, call ABI and runtime dependencies stay the same. The ordinary and per-unit paths share admission. The existing SIMD and mask rules are the prerequisite. draft §9, the language digest, design notes, settled decisions, the checked-HIR ledger and the English and Japanese vec-mask references record the public contract. |
| Acceptance | The `vec_simd` owner covers every lane width and numeric family, scalar on each side, cross-family structural masks, nested literal inference, signedness, width and scalar-only errors. The imported generic source fixture checks early exits from each argument, evaluation order and exact NaN, negative-zero and high unsigned bits in whole-program and cold/warm unit execution. `select_broadcast_checked_hir_and_make_vec_producers` mutates recorded operand/result types, scalar MIR blend arms, short/long lane lists, invalid widths, mislabeled constants and detached operands in whole and partition validation. Existing vector/vector and integer division broadcast owners cover the shared lowering. |
