# Session resumption for an explicitly configured HTTPS origin

| Contract | Semantics and acceptance |
|---|---|
| Source and configuration | Extend the origin-scoped http.tls_client constructor with one optional final resume_sessions: bool = false. Its existing five arguments precede the flag. The default http.client and every call that omits the flag retain their present policy. This choice stays fixed for the life of the constructed client and travels through its existing Move and pool ownership. No other setter or import/export for raw tickets is exposed. The original constructor's descriptor, origin, pair, trust and CRL validation take their existing order. An enabled policy requires explicit trust roots and empty CRLs. A private store constructed from the supplied roots fixes the trust decision for this client. Evaluate the sixth expression once with all five earlier views live. For native validation check/clear the output first, validate the five raw descriptors in order, then accept only the raw flag 0 or 1. Check origin, pair, CRL trust prerequisite, then resumption root/CRL compatibility before PEM parsing in ordinary constructor order. Invalid raw flag and incompatible policy both return Invalid. |
| Scope and limits | One bounded slot, exclusive to one client, one immutable OpenSSL context, canonical HTTPS origin/port, certificate identity and root set. Only a fresh TCP connection can offer a saved session. Select a pooled live connection first. Take the single entry under the existing synchronization discipline, without holding a lock over network I/O. Free the application's reference after SSL_set_session takes its own; a missing, ineligible or expired entry selects the ordinary full verified handshake on that connection. An SSL_set_session engine failure closes the uncommitted SSL and fd with the existing mapped setup error. A peer declining a ticket may perform a full verified handshake on the same connection. Handshake or I/O failure after that point follows the ordinary transport contract. No replay or retry of HTTP requests is introduced. |
| Capture | For eligible private SSL_CTX instances install the client new-session callback with internal storage/lookup disabled. SSL ex_data points only to state owned as long as the specific SSL; duplicate each eligible newly negotiated session with SSL_SESSION_dup while its originating SSL is exclusive, return 0 to release the callback-supplied reference on every branch, and own only the most recent successful duplicate. A single process-initialized ex_data index points to stable per-SSL storage until after SSL_free. Disable TLS 1.2 renegotiation and leave post-handshake client authentication disabled on these contexts. On optional capture allocation failure discard the pending ticket and isolate its OpenSSL error-queue entries from surrounding TLS I/O status. Delay publication until a complete authenticated HTTP response and verified handshake. Certificates, tickets and keys stay in native memory. Release pending and replaced references exactly once on every path, including callback during shutdown, failure, concurrent requests and client Drop. Each dequeued issuance is offered at most once. Separate peer issuances can carry identical wire bytes. Accept TLS 1.2 session IDs or tickets, and only resumable TLS 1.3 tickets. The callback must supply a new issuance to restock the cache after a hit. At successful completion of an exchange, take and clear its pending slot before pooling or closing the SSL. An individual successful get_many exchange may publish despite a failed sibling. Include terminal bodyless, raw and SSE successes. An unfinished body, abandonment, shutdown callback or failed exchange never publishes; clear staged tickets there. Later callbacks observed on an active pooled exchange can publish only on that exchange's complete success. Concurrent publication uses last eligible completion order. Failed, abandoned or unread response streams never contribute pending state; no extra read or forced wait solely to acquire a ticket. |
| Authentication and time | Inspect SSL_session_reused after every successful SSL_connect. For full/fallback handshakes require X509_V_OK and fresh owned evidence from that handshake's verified chain including its anchor. For resumed handshakes require the exact evidence from the consumed issuance. Sample both clocks at full verification. Carry an immutable checked validity interval equal to the intersection of every certificate in the verified path, the configured client identity chain if present, and the native session validity. Re-check against wall time (including backward jumps) and elapsed monotonic age immediately before offering; cap elapsed age at 90 seconds from full verification. Use checked half-open intervals for both native session lifetime and certificate boundaries, with proof valid only for monotonic age strictly less than 90 s. TLS 1.3 additionally caps the interval by the server ticket lifetime hint measured from that issuance and discards a zero hint. For TLS 1.2 a zero advisory ticket hint or ID-only issuance uses the native session lifetime plus the certificate and 90 s limits. Reissued tickets after resumption cannot extend the original authentication interval or age. Invalid or unavailable time, missing chain evidence, malformed interval, expired session, or a non-resumable provider state prevent the offer. Recheck all wall-time and monotonic bounds after a resumed handshake before writing any HTTP bytes. A live already pooled TCP connection retains the separate established-connection lifetime policy. Reject expired verification with Denied. Initial and fallback full handshakes rebuild the verified-chain interval and check it again immediately before HTTP. In this opt-in mode every configured client certificate must also be current at this check, including when the peer does not request a client certificate. An expired, premature, malformed or missing required certificate yields Denied; inability to sample the clocks or initialize native time storage on a full handshake yields Code(0). Keep host/IP checks, ALPN, TLS 1.2 minimum and existing I/O deadlines. No TLS early data is sent. |
| Ownership and cache | All process-wide default-client contexts and pools remain independent. Client mutex operations only move at most one owned session reference. SSL-local pending and origin verification data cannot outlive the SSL or point at an already dropped client. Retain only the one newest eligible callback for a connection. A new eligible completion replaces the slot, and both release paths run outside the cache lock. Last client Drop frees connections and pending sessions with their contexts alive. Never log or serialize session material. Raw TLS FFI calls capture SSL/errno status in the order established by the mTLS owner. |
| Implementation and evidence | Reuse the mTLS constructor and checked-HIR/MIR bool typing. Update align_rt_http_tls_client_new to i32(ptr origin,i64 len,ptr trust,i64 len,ptr chain,i64 len,ptr key,i64 len,ptr crls,i64 len,i32 resume_sessions,ptr out). Both an absent flag and explicit false yield the identical zero discriminator. Normal/cache/feature admission and the declaration golden change with it. Test direct malformed raw flag/descriptor/conflict combinations, output clearing, unused malformed HIR, side-effectful sixth argument and earlier-view invalidation. Include the immutable mode in runtime object's policy; compiler module/cache identities follow the changed MIR/ABI. The explicit mode is Impure like the existing constructor. OpenSSL integration covers TLS 1.2 and 1.3, two distinct accepted sockets, SSL_session_reused on both ends, late/multiple/no tickets and full server fallback. Controls cover origin/port/client separation, trust identity, full authentication expiry, inherited age, invalid config, invalid native bool, concurrent single use, early Drop and error cleanups, default-disabled behavior, no early HTTP data, and stream/batch/eager request consumers. The clock owner separates ages 89/90 s, wall-clock rollback, a handshake spanning expiration, successor issue time, and native lifetime versus protocol hint. Include an explicitly rekeyed untrusted server on fallback with zero transmitted HTTP bytes, TLS 1.2 ID-only and ticket controls, concurrent capture and teardown of the producer after the second worker checks out, no successor on a hit, and successful/failed terminal per-exchange capture. Measure full vs resumed handshake over new local sockets; record actual selection counts alongside latency. |

The native reference and timing rules follow the OpenSSL manuals for [new-session callbacks](https://docs.openssl.org/3.0/man3/SSL_CTX_sess_set_get_cb/), [session lifetime](https://docs.openssl.org/3.0/man3/SSL_get_session/) and [offering a session](https://docs.openssl.org/3.0/man3/SSL_set_session/).

## Implementation closure

| Boundary | Verification |
|---|---|
| Construction, call and transfer | Source argument ordering and generation, checked HIR, SSA dominance, whole and unit lowering, raw discriminator and output validation share the existing Move HTTP client. Exercise omitted, explicit, erroneous and terminal values, imported generic functions and warm cache. |
| OpenSSL context, connection and issuance | A client owns one synchronized slot and each SSL owns its pending callback reference. Check setup failure, acquisition, rejection, replacement, full fallback, early Drop, parallel checkout and destruction. Inspect actual offers and selections on distinct sockets in both protocol versions. |
| Authentication and clocks | Every issuance retains the original full-handshake evidence. Check both ends of certificate and native session validity, 90-second monotonic expiry, clock rollback and session successor bounds. |
| HTTP completion | Commit captures on successful eager, bodyless, completed raw stream and SSE paths. Discard partial/error, abandoned and shutdown-time captures. Check both close and keepalive. |
| Capability and measurements | Compiler, native state machine and consuming request paths ship together so every offer can be authorized and retired. The handshake comparison records actual full/resumed counts and elapsed times; it sets no performance threshold. |

The local OpenSSL 3.5.7 loopback owner measured 40 requests per setting, each on a new TCP connection. With resumption disabled, median request time was 1.89 ms for TLS 1.2 and 1.75 ms for TLS 1.3. With resumption enabled, TLS 1.2 selected 20 resumed requests at a 1.13 ms median and 20 full requests at 1.90 ms. The local server issued no successor on those TLS 1.2 hits. TLS 1.3 selected all 40 resumptions at a 1.45 ms median. The measurement includes TCP connect and a complete HTTP exchange.
