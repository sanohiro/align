# Origin-scoped HTTPS clients with explicit trust and identity

The model-download fixture currently selects a private root through a process environment variable. A client configured from bytes can instead isolate verification policy and optional credentials within the existing HTTP request family. The capability ships credential decoding, immutable client ownership and every consuming request path together. Each intermediate on its own would create an unconsumed crypto capability or an origin-isolation gap. Server-side termination and TLS ticket reuse are separate boundaries.

| Surface | Contract and evidence |
|---|---|
| Source | `http.tls_client(origin: str, trust_pem: bytes, certificate_chain_pem: bytes, private_key_pem: bytes, crls_pem: bytes) -> Result<http_client, Error>`. All arguments required. The ordinary `http.client()` continues to select process system roots for general HTTP/HTTPS; a configured client is for exactly one HTTPS origin. Empty trust selects system verification. A nonempty list replaces the trust store with its declared anchors. A certificate and unencrypted PKCS#8 private key select mutual TLS as an inseparable pair. Two empty fields omit client credentials. An empty CRL list selects ordinary chain+host validation; a nonempty list requires nonempty explicit trust and selects mandatory offline revocation of the complete peer chain. Reject empty trust plus supplied CRLs as Invalid before accessing system defaults; the ambient OpenSSL file/directory can itself contain CRLs. Explicitly changing policy means constructing a new client and pool. |
| Origin | Require a valid UTF-8 ASCII HTTPS origin (lowercase https scheme, host, optional port and optional single slash); reject credentials, query, fragments, zone IDs, embedded NUL, controls, raw spaces, non-ASCII hostnames, empty or signed/non-decimal port, ports outside 1..65535 and arbitrary paths. DNS names are complete ASCII labels (letters/digits/hyphen, no empty or edge-hyphen labels, maximum 63 octets/label and 253 total). One trailing dot is rejected rather than silently changing SNI. IPv6 literals require brackets and parse as IPv6. IPv4 literals use decimal dotted-quad `Ipv4Addr` parsing; reject ambiguous legacy numeric spellings. Store DNS in lowercase ASCII, numeric IPs in address-family+octets, and normalize absent port to 443. On each request derive the same origin from its URL and compare before DNS, pool checkout, serialization containing credentials, connect, or handshake. Malformed request returns Invalid; well-formed mismatched HTTPS authority or HTTP scheme returns Denied. The existing HTTP stack does not automatically follow redirects. No DNS alias, user-supplied Host header, case variation, default port or session can bypass scope. The serializer generates exactly one Host; reject all caller-supplied Host fields as the existing serializer does. Scoped requests admit only RFC token header names and reject caller-supplied Host, Content-Length and Transfer-Encoding fields. Preserve the existing CONNECT prohibition, then validate method token, URL and origin grammar, request target (slash-led ASCII path, optional query, no fragment, control byte or spaces), reserved names/header values, then enforce origin equality, all before acquiring a connection. A query after an empty path must spell the slash. Send only the canonical origin host to the resolver, SNI (DNS only), verification and pool key. Consume and drop a request on rejection. Batch get_many joins every worker, frees successes on error and returns the lowest-index failed entry's error. Admitted siblings may perform I/O; denied entries never do. |
| PEM | Each PEM field is a byte view with explicit length. Exact ASCII labels CERTIFICATE, PRIVATE KEY, and X509 CRL respectively. One or more objects for nonempty trust, chain and CRLs; exactly one key. Optional surrounding/inter-object ASCII SP, TAB, CR or LF, LF or CRLF line endings. Reject any NUL, other text, unlabeled/unknown/wrong/encrypted block, invalid base64, empty payload or trailing DER bytes. Allow at most 4 MiB per encoded field, 64 certificates per list, 64 CRLs, and exactly one key of at most 64 KiB in decoded form. Count and bound input before allocating native objects; reject over-limit inputs as Invalid. Use canonical padded base64 with exact end-of-input, no whitespace within encoded lines and no residual pad bits. Use OpenSSL's native ASN.1 acceptance for X.509 certificates, CRLs and PKCS#8 PrivateKeyInfo (DER and the BER encodings accepted by the target OpenSSL 3 decoder). Require a complete, single object with no extra bytes; do not claim ASN.1 canonicalization from d2i or from i2d of a cached X509. The certificate/key pair must be accepted by the active TLS provider. The digest/signing library's narrower algorithm selection is independent. Reuse the existing PEM/base64 padding checks and native secret-allocation/error-queue helpers where applicable. Bound decoded lengths using checked arithmetic. No password prompting, file access for explicit credentials, global variable or process signal mutation. The input bytes remain borrowed only through the call. Zero temporary private-key decoded DER via OpenSSL's cleanse on all paths. No argument bytes in diagnostics. OpenSSL owns the parsed key. Prevalidate sizes according to actual native length widths before conversion. |
| Error order | Evaluate origin, trust, chain, key and CRLs once left-to-right, protecting earlier views through later evaluation and unwinding temporaries on an early return. Once all values exist, first clear a writable out handle; null out is Invalid before any other work. Validate each native descriptor in source order: len=0 accepts a null or nonnull pointer; positive length requires nonnull and representable, addressable range and within the field's declared bound; any negative length is Invalid. Valid caller memory is still the native ABI precondition. Never use the normalizing bytes_view for malformed inputs. Validate origin (maximum 268 UTF-8 bytes including port), credential pair presence, nonempty explicit trust for CRL mode, trust list, chain list, private key and key match, then CRLs in supplied order, all before publishing or network activity. Malformed credentials, unpaired/mismatched key/cert, unsupported encoding or an explicit CRL with missing mandatory freshness bounds returns Invalid; allocation/initialization failures use the shared AL_CODE fallback (Error.Code(0), or the existing platform error for a syscall), and local certificate verification failure uses Denied. A TLS alert sent by the peer rejecting the client's identity follows the existing SSL error mapping, including Invalid when the local verify result is OK, at handshake or subsequent I/O. Clear the thread-local OpenSSL error queue before each operation whose result is classified; capture errno/SSL_get_error immediately with no intervening native calls, then drain the queue. Check every fallible SSL setup return (including minimum version, SNI, verification target and signing algorithm setup). Existing verification failures (including missing, expired, incorrect-signature or revoked CRLs at handshake) use Error.Denied; network and TLS deadlines retain existing mappings. Initialize the mandatory peer-verification flag, TLS1.2 floor, default or private store, optional chain and key with an explicit positive key-match check. Never accept a partial list after an error. |
| Objects and trust | Trust PEM accepts distinct self-signed CA certificates with basicConstraints CA=true and a valid self-signature; reject duplicates, non-self-signed/leaf anchors and partial chains. Use a newly allocated private X509_STORE with no ambient lookup for nonempty trust. Chain PEM requires a non-CA leaf first and non-self-signed CA intermediates in declared issuer/signature order, no duplicates, no appended self-signed root. Disable OpenSSL outgoing chain auto-building and install the explicit chain separately from the verification store. Verify the actual peer-observed certificate fingerprints and order, including a leaf-only case in which local roots could otherwise be appended. Ordinary peer verification always checks the actual remote identity at handshake, independent of the presented client credential. Supply CRLs to the configured store and enforce OpenSSL's CRL_CHECK plus CRL_CHECK_ALL. Admit full direct CRLs only (reject deltaCRLIndicator, issuingDistributionPoint and indirect/scoped evidence); one CRL per issuer compared by X509_NAME_cmp. Reject missing, malformed or nonincreasing lastUpdate/nextUpdate locally. At every handshake the current clock must be inside the evidence validity interval, and OpenSSL must validate issuer/signature/coverage for each member of the selected chain, including the anchor. Missing/wrong issuer, signature, expired/future evidence or revocation yields Denied. Ambient CRLs cannot complement an explicit store. In CRL mode do not return idle TLS connections for reuse and disable ticket/session resumption; every request or reconnect revalidates against current time and immutable evidence. No CRL/OCSP fetch. Already checked-out streaming exchanges retain their established connection until normal finish, timeout or Drop. Tests must prove trust/client-key isolation, wrong issuers and time rollover. |
| Compiler and ABI | New impure checked HIR/MIR operation yields the existing Result<http_client, Error> ownership boundary; exact native key `align_rt_http_tls_client_new` with i32(ptr origin,i64 length,ptr trust,i64 length,ptr chain,i64 length,ptr key,i64 length,ptr crls,i64 length,ptr out). Failure clears a writable result slot; null output returns Invalid. Success publishes one Move client exactly once. All six pointers conservative Foreign/Unstated; the returned client owns its SSL_CTX and normalized origin until its existing Drop, including pooled connections and aliases outstanding under the existing borrow rules. The constructor holds each decoded X509/X509_CRL/EVP_PKEY under a scope guard until a checked add1/up-ref/store operation has acquired its own reference, then drops the temporary; it frees SSL_CTX on every late failure. The client closes each pooled SSL/fd and releases its own SSL_CTX once; an SSL retains its own reference through its exchange and is dropped before its fd. Secret buffers are cleansed without logging. No process-shared mutable credential store. Existing source/cache identities must identify all ordered children and the operation; complete generic replay, capture, whole/Thin/unit cache and LLVM ABI inventory. No new platform library or native package. Source-of-truth updates draft, language digest, open questions, std-design/http and client-composition as applicable and Japanese mirrors, ledgers 19/20. |
| Acceptance | Use real localhost TLS peers for system and private trust, custom-root-only despite also-valid system root, mutual TLS with correct client cert, absent/wrong identity, wrong hostname/IP, malformed second PEM after a valid first block, mismatched key, public key/encrypted key/extra block/non-ASCII/NUL, and multi-invalid input. Demonstrate configured clients concurrently holding different roots/identities including get_many. Confirm other-origin HTTP and HTTPS never touch listeners, including forced Host and stale-pool retry. Cover get/post/request/stream, peer verification for reused vs new connections, revocation before and after expiration, invalid signatures/missing CRL for an intermediate, leaf and intermediate revocation. Cover each malformed pointer/length independently, duplicate/forged Host denial before DNS, mixed get_many success and error-index precedence, custom anchors without ambient CRLs, observed leaf-only and multi-element wire chains, same-thread malformed PEM followed by a real TLS timeout/peer alert, and failure after each ownership transfer. Track native frees and fds for constructor error, pooled client Drop, early terminal errors and retained stream. Validate mapped error precedence, cross-function inferred/explicit carriers, owned moves and malformed unused HIR before summary; no throughput promise. |

## Implementation closure

| Boundary | Implementation and owner |
|---|---|
| Construction and transfer | Source admission, HIR replay, ordered input views, terminal evaluation, MIR status and client publication, whole and per-unit code generation share the existing Move client and Result rules. Check source rejection, unused malformed IR, an imported constructor, propagation, reassignment and early Drop. |
| Policy and native ownership | The runtime constructor, explicit OpenSSL context and retained origin own every parsed object. Check malformed fields, allocation failure, cleanup, partial chains, peer-observed chain order, CRL coverage and independent clients with loopback transport. |
| Requests and pooling | Eager and streaming send paths authorize the normalized HTTPS origin before acquisition. Batch workers invoke the same eager path. Check HTTP and wrong-port denial, method and header validation, effective timeouts, stale retries, stream teardown and fresh verification when CRLs are configured. |
| Artifact and scope | Audit the TLS capability, exact exported native declaration and linked runtime on all supported platforms. Credential parsing, pool isolation and all request consumers share the same context identity. Keeping them in one capability avoids publishing an incomplete authorization policy even when the implementation exceeds 1,000 hand-written lines. |

OpenSSL owns native chain references and associates each client context with its trust and identity. [Certificate chain ownership](https://docs.openssl.org/3.0/man3/SSL_CTX_add1_chain_cert/) and [verification flags](https://docs.openssl.org/3.0/man3/X509_VERIFY_PARAM_set_flags/) define the corresponding native operations.
